# ۵. ابزارها، فناوری‌ها و حجم بالا

> همه‌ی ابزارها **رایگان و متن‌باز**ند. نسخه‌ها هنگام ساخت **ثابت (pin) و با hash** میشوند.

## پنل مرکزی
| لایه | انتخاب | چرا |
|---|---|---|
| زبان | Python 3.12+ | SDK رسمی هتزنر (`hcloud`) و بهترین کتابخانه‌های تلگرام را دارد. |
| API و داشبورد | **FastAPI** + Pydantic v2؛ رابط وب سبک (HTMX یا React) | async است و برای هزاران رویداد تلگرام در دقیقه کافی است. |
| دیتابیس | **PostgreSQL 16** + Alembic | منبع حقیقت. `advisory lock` برای چرخه‌ها. |
| اتصال دیتابیس | asyncpg + **PgBouncer** (وقتی worker زیاد شد) | |
| صف و قفل و نرخ | **Redis 7** | قفل توزیع‌شده، سقف نرخ تلگرام و هتزنر (token bucket)، cache. |
| کارهای پس‌زمینه | **Dramatiq** یا **arq** روی Redis؛ زمان‌بندی با APScheduler یا cron داخلی | سبک است. Temporal برای این اندازه سنگین است. اگر کارها خیلی چندمرحله‌ای شدند، Temporal دوباره سنجیده شود. |
| ربات تلگرام | **aiogram 3** (async) در حالت **webhook** | رویداد `chat_member` و ویرایش پست. webhook از polling مقاوم‌تر است. |
| هتزنر | **`hcloud-python`** (SDK رسمی) | سرور، Primary IP، فایروال، snapshot، برچسب. |
| image | **Packer** + پلاگین `hcloud` | snapshot آماده‌ی node (`03_NODES.md`). |
| ارتباط با node | **mTLS** (CA خود پنل، گواهی کوتاه‌عمر) | node به پنل وصل میشود (pull). SSH لازم نیست. |
| اجرا | **Docker Compose** روی سرور پنل، با healthcheck و `restart: unless-stopped` | ساده است و برای یک سرور کافی است. |
| لبه | **Caddy** (HTTPS خودکار) | داشبورد و webhook تلگرام. |

## node
| جزء | انتخاب |
|---|---|
| هسته‌ی پروکسی | **Xray-core**، کنترل با gRPC API خودش (HandlerService برای افزودن و حذف کاربر بی restart، StatsService برای مصرف) |
| MTProto | `mtprotoproxy` یا MTProxy رسمی؛ باید ad tag و fake-TLS داشته باشد (انتخاب در فاز ۲) |
| عامل node | یک باینری کوچک **Go** (کم‌مصرف، یک فایل) یا Python. **پیشنهاد: Go.** |
| فایروال | nftables داخل node و فایروال هتزنر جلوی node |
| کرنل | BBR، `fq`، بافرهای شبکه‌ی بزرگ‌تر، `nofile` بالا |

> **چرا پنل آماده (Marzban یا 3x-ui) نه:** این پنل‌ها برای مدیریت دستی ساخته شده‌اند. ما چرخه‌ی کنترل، اسپانسر، CRM و بودجه را خودمان داریم. کنترل مستقیم Xray با API آن ساده‌تر و مقاوم‌تر است. Marzban فقط مرجع خوبی برای ایده است.

| کار | ابزار |
|---|---|
| متریک‌ها | **Prometheus** (پنل و آمار کلی nodeها) + **Grafana** برای داشبورد فنی |
| لاگ پنل | **Loki** یا لاگ JSON با چرخش. هیچ لاگ کاربری از node نمیآید. |
| هشدار | **Alertmanager**، با پیام تلگرام به چت خصوصی مالک |
| نگهبان بیرونی | یک سرویس بیرونی رایگان heartbeat (healthchecks.io یا یک cron روی جای دیگر). اگر خود پنل خوابید، کسی خبر بدهد. |
| backup | `pg_dump` و **restic** به **Hetzner Object Storage** یا Storage Box، رمزنگاری‌شده، با آزمون بازگردانی هفتگی |
| رمزها | فایل env با دسترسی `600` بیرون از ریپو، یا **SOPS + age**. هیچ رمزی در ریپو نیست. |
| CI | GitHub Actions: lint (ruff، mypy)، تست، gitleaks، ساخت image |

## حجم بالا: گلوگاه‌ها کجاست
بار اصلی روی **nodeها** است، نه پنل. پنل حتی با صدها node و صدها هزار عضو سبک میماند.

| گلوگاه | سقف (هنگام ساخت سنجیده شود) | راه حل |
|---|---|---|
| **API هتزنر** | حدود ۳۶۰۰ درخواست در ساعت برای هر project | سقف نرخ در Redis؛ خواندن دسته‌ای (list با برچسب)، نه تک‌تک؛ cache وضعیت |
| **سقف منابع حساب هتزنر** | حساب تازه سقف کمی برای تعداد سرور دارد | در کنسول هتزنر درخواست افزایش سقف. **کار مالک در فاز ۰.** |
| **ترافیک هر node** | سرورهای اروپایی سهم ترافیک ماهانه‌ی زیادی دارند (حدود ۲۰TB). اضافه‌اش پولی است. | عامل مصرف ماه را میشمارد. چرخه‌ی `budget` پیش از رسیدن به سقف، بار را به node دیگر میبرد. |
| **CPU و اتصال هر node** | یک node کوچک با Reality و Vision هزاران اتصال سبک را میکشد (عدد واقعی در فاز ۶ با آزمون بار) | کانفیگ‌ها روی nodeها پخش میشوند؛ کانفیگ تازه روی کم‌بارترین node |
| **تلگرام** | حدود ۲۰ پیام در دقیقه در هر کانال، و حدود ۳۰ پیام در ثانیه در کل | صف و token bucket. ویرایش‌ها دسته‌ای و آرام. |
| **رویدادهای CRM** | در روزهای پربازدید هزاران عضویت در ساعت | webhook فقط ذخیره میکند و سریع 200 میدهد. پردازش در صف است. ردیف‌ها idempotent‌اند (`update_id`). |
| **دیتابیس** | — | ایندکس روی `telegram_user_id` و `created_at`. اگر جدول رویدادها خیلی بزرگ شد، partition ماهانه. |

## آزمون‌ها پیش از «تمام شد» هر فاز
- **واحد و یکپارچه:** API هتزنر و تلگرام با نسخه‌ی جعلی (fake) شبیه‌سازی میشوند. هیچ تستی سرور واقعی نمیسازد.
- **آزمون آشوب (chaos):** پنل وسط ساخت node کشته میشود؛ node بی‌خبر خاموش میشود؛ تلگرام 429 میدهد. سیستم باید بدون دخالت درست شود.
- **آزمون بودجه:** با هزینه‌ی جعلی نزدیک سقف، هیچ node تازه‌ای ساخته نشود.
- **آزمون حذف:** کد هرگز سروری بی برچسب، یا بی ردیف دیتابیس، را حذف نکند.
