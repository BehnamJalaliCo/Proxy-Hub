# ۹. خطرها و راه مقابله

| # | خطر | اثر | راه مقابله |
|---|---|---|---|
| R1 | **abuse و قفل شدن حساب هتزنر** | اگر حساب مشترک باشد، **سرورهای اصلی مالک** هم درگیر میشوند | حساب جدا (O1)؛ بستن ایمیل، تورنت و رنج خصوصی؛ سقف حجم؛ retire فوری node گزارش‌شده |
| R2 | **توکن با دسترسی بیش از حد** | حذف اشتباه سرورهای دیگر | project جدا؛ قفل حذف دوگانه؛ اگر سرور ناشناس دید، چرخه‌ی fleet روشن نمیشود |
| R3 | **فیلترینگ گسترده‌ی رنج‌های هتزنر** | همه‌ی nodeها با هم میسوزند | چند منطقه؛ هشدار «سوختن گسترده»؛ فاز بعد: مسیر CDN |
| R4 | **خرج بی‌کنترل** (حلقه‌ی ساخت، ترافیک اضافه) | فاکتور بزرگ | سقف بودجه، سقف تعداد، سقف سرعت ساخت؛ شمارش ترافیک هر node |
| R5 | **کانال تلگرام گزارش یا محدود شود** | از دست رفتن مخاطب | CRM و ربات اختیاری (O6)، تا مخاطب فقط در یک کانال نباشد؛ یک کانال پشتیبان |
| R6 | **نشت توکن ربات** | پست یا ویرایش نامطلوب | توکن فقط روی پنل در فایل `600`؛ ربات اجازه‌ی حذف ندارد؛ `/revoke` در BotFather |
| R7 | **تغییر رفتار تلگرام** در ad tag یا @MTProxybot | از دست رفتن کانال اسپانسر | بقیه‌ی ابزار رشد (تبلیغ پست، لینک دعوت) مستقل‌اند؛ پایش «عضو از اسپانسر» |
| R8 | **تغییر روش فیلترینگ** (DPI تازه) | Reality یا MTProto کار نمیکند | probe ایران زود میفهمد؛ پروتکل‌ها افزونه‌ای‌اند و افزودن پروتکل تازه فقط image تازه میخواهد |
| R9 | **نشت داده‌ی کاربران** | خطر برای کاربران | هیچ IP و ترافیکی ذخیره نمیشود؛ CRM فقط داده‌ی خود تلگرام است؛ backup رمزنگاری‌شده |
| R10 | **افتادن پنل** | پست تازه نمیآید | nodeها مستقل کار میکنند؛ نگهبان بیرونی؛ بازیابی با دامنه و backup |
| R11 | **حساب تلگرام یا فیسبوک ساخته‌شده با ربات یا سرور مسدود شود** (تجربه‌ی IG-Hub) | از دست رفتن ابزار | هر حسابی (تلگرام، ربات، @MTProxybot) را **خود مالک** از دستگاه خودش میسازد |
