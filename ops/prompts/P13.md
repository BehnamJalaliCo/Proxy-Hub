# پرامپت ۱۳: کانفیگ با دامنه‌ی خود سرور (D42)، آزمون واقعی از ایران

> مالک این را میچسباند: «`git pull` بزن (روی `main`)، بعد فایل `ops/prompts/P13.md` را بخوان و دقیق اجرا کن.»

قاعده‌های `ops/prompts/README.md` برقرار است:
- فارسی با مالک، و **کوتاه**.
- هیچ رمز، کلید، لینک کانفیگ، uuid یا secret در گزارش نیاید.
- commit یا push نکن.

**هدف:** کانفیگ‌ها حالا VLESS + WebSocket + TLS هستند، روی نام خود node و با گواهی واقعی Let's Encrypt. MTProto هم همان نام را میگیرد. این را روی یک node آزمایشی تازه بسنج و از ایران امتحان کن.

فرمان‌ها:
- `C="sudo docker compose -p proxyhub exec -T api python -m proxyhub.nodes"`
- `Q() { sudo docker compose -p proxyhub exec -T postgres psql -U proxyhub -d proxyhub -At -c "$1"; }`

1. **پیش‌شرط:**
   - `sudo bash ops/scripts/deploy_status.sh` باید `branch: main` و `RESULT: up to date` بدهد.
   - `Q "SELECT version_num FROM alembic_version"` باید `0018_wstls` بدهد.
   - worker بی خطا بالا آمده باشد. این دستور باید ۰ بدهد: `sudo bash /opt/proxy-hub/deploy/monitoring/safe_logs.sh worker 300 | grep -ciE "traceback|failed; retrying"`
2. **گواهی** (تا ۱۰ دقیقه پس از استقرار):
   - `Q "SELECT domain, not_after, attempts, last_error FROM acme_certificates"` باید برای دامنه‌ی فعال یک `not_after` در حدود ۹۰ روز بعد نشان دهد و `last_error` خالی باشد.
   - اگر خطا بود، `last_error` و ۳۰ خط لاگ worker را گزارش کن و ادامه نده.
3. **node آزمایشی تازه** (مالک در داشبورد):
   - node آزمایشی قبلی عامل قدیمی دارد. «بازنشسته کردن» را بزنید و صبر کنید تا حذف شود: `$C wait <ID قبلی> deleted --timeout 600`.
   - کلید توقف خاموش بماند. سقف node یک و حالت خشک روشن بماند.
   - «ساخت node آزمایشی» را بزنید. سپس `$C wait <ID> ready --timeout 1500`.
4. **سنجش از سرور پنل** (`<name>` همان `t<hex>.<دامنه>` است که صفحه‌ی Reality نشان میدهد):
   - `dig +short <name> @1.1.1.1` باید IP همان node را بدهد.
   - `openssl s_client -connect <ip>:443 -servername <name> -alpn http/1.1 </dev/null 2>/dev/null | grep -E "Verify return code|ALPN"` باید `Verify return code: 0` و `http/1.1` بدهد.
   - تا ۲ دقیقه، صفحه‌ی Reality باید یک کانفیگ فعال `type=ws` نشان دهد.
   - `Q "SELECT tls_domain FROM telemt_node_configs WHERE node_id='<ID>'"` باید همان `<name>` باشد.
   - `openssl s_client -connect <ip>:8443 -servername <name> </dev/null 2>/dev/null | grep "Verify return code"` باید `0` بدهد.
5. **از ایران** (مالک، با گوشی، **VPN خاموش**). از مالک بخواه:
   - «در صفحه‌ی Reality، لینک کانفیگ تازه را کپی و در V2BOX وارد کنید. وصل شوید، سایت fast.com را باز کنید و عدد سرعت را بگویید.»
   - «در صفحه‌ی پروکسی‌های MTProto، لینک را در تلگرام باز کنید، Connect را بزنید و Use Proxy روشن بماند. یک ویدیو باز کنید. دانلود شد؟»
   - «اپراتور و وای‌فای یا اینترنت گوشی؟»
6. **اسپانسر** (اصلاح PR ۱۰ مستقر است):
   - `Q "SELECT action FROM actions_log WHERE action LIKE 'sponsor%' ORDER BY id DESC LIMIT 15"` را بگیر.
   - اگر `registered` و `tag_applied` آمد، عالی است.
   - اگر صفحه‌ی «اسپانسر» گفت متوقف است، از مالک بخواه **یک بار** «ثبت دوباره» را بزند. اگر باز شکست خورد، متن خطا را بی secret گزارش کن.
7. **گزارش پایانی** در یک بلوک کوتاه برای Claude ریپو: نتیجه‌ی هر گام، عدد سرعت، و MTProto دانلود کرد یا نه.
   - node آزمایشی را نگه دار. کلید توقف را به مالک بسپار.

**نکن:**
- تنظیمات ناوگان را عوض نکن، و بیش از یک node نساز.
- `git push` نکن.
