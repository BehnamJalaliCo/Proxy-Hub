# پرامپت ۲۷: حساب هتزنر پر است؛ سنجش جا و Primary IPها (فقط خواندن)

> مالک این را میچسباند: «`git pull` بزن (روی `main`)، بعد فایل `ops/prompts/P27.md` را بخوان و تا رسیدن به نتیجه، خودت اجرا کن.»

قاعده‌های `ops/prompts/README.md` برقرار است:
- فارسی و **کوتاه** با مالک.
- هیچ رمز، توکن، IP کامل یا لینک کامل پروکسی در گزارش نیاید.
- commit یا push نکن.

فرمان‌ها:
- `Q() { sudo docker compose -p proxyhub exec -T postgres psql -U proxyhub -d proxyhub -At -c "$1"; }`
- `N="sudo docker compose -p proxyhub exec -T api python -m proxyhub.nodes"`

**این پرامپت چیزی را عوض نمیکند.** فقط میسنجد و گزارش میدهد.

**چرا:**
- هتزنر در P26 ساخت سرور پنجم را رد کرد (`resource_limit_exceeded`، از نوع `primary_ip_limit`). ناوگان از آن موقع سقف را **۴ سرور** میداند.
- مالک نمیتواند سقف را بالا ببرد.
- سوخته‌ها از PR ۳۰ (D57) خودکار جا باز میکنند. ولی حالا هر ۴ جا را سرورهای سالم گرفته‌اند: ۳ node جایگاه‌دار و node آزمایشی.
- هتزنر سقف Primary IP را **دو برابر** سقف سرور میگذارد، و هر سرور یک IPv4 و یک IPv6 میگیرد.
- اگر در project، Primary IP بی‌سروری مانده باشد، از جای سرورها کم میکند. این پرامپت همین را میسنجد.

**چه عوض شد (PR ۳۳):**
- `$N servers` حالا برای هر حساب این‌ها را هم نشان میدهد: `learned_server_limit` و `primary_ips` (شمار ipv4 و ipv6، و آن‌هایی که به هیچ سروری وصل نیستند، با id و نام، بی نشانی).
- پیام «حساب هتزنر پر است» حالا سقف را میگوید، node آزمایشی را یادآوری میکند و حداکثر **هفته‌ای یک بار** تکرار میشود، نه هر ۱۲ ساعت.

0. **پیش‌شرط:** `deploy_status.sh` باید `RESULT: up to date` بدهد. شمار خطای worker باید ۰ باشد.
1. **ناوگان در پایگاه‌داده:**
   - `Q "SELECT is_test, slot, state, location FROM nodes WHERE state <> 'deleted' ORDER BY is_test, slot"`.
   - `Q "SELECT name, state, learned_server_limit FROM hetzner_accounts"`.
   - `Q "SELECT at, context->>'kind', context->>'servers_in_account', context->>'learned_server_limit' FROM actions_log WHERE action = 'learned_server_limit' ORDER BY at DESC LIMIT 3"`.
   - `Q "SELECT code, active, since, last_sent_at, detail FROM fleet_alerts ORDER BY code"`.
2. **نگاه زنده به هتزنر:** `$N servers`. برای هر حساب گزارش کن:
   - شمار سرورهای ما (`ours`)، و از میانشان چندتا `purpose=test` اند؛
   - `others`، که باید ۰ باشد؛ اگر نبود، **بایست و به مالک بگو** (CLAUDE.md، قاعده‌ی ۴)؛
   - `learned_server_limit`؛
   - `primary_ips`: شمار ipv4 و ipv6، و فهرست `unassigned` (id، نوع، نام، `auto_delete`).
3. **داوری** (فقط گزارش):
   - اگر ipv4 + ipv6 برابر «۲ × شمار سرورها» است و `unassigned` خالی است، حساب واقعاً پر است. با سقف ۴، بیشترین ناوگان ۴ سرور است.
   - اگر `unassigned` خالی نیست، این IPها جای سرور را گرفته‌اند. **پاکشان نکن.** id و نامشان را گزارش کن تا Claude ریپو با مالک تصمیم بگیرد.
4. **گزارش پایانی** در یک بلوک کوتاه برای Claude ریپو: ردیف‌های گام ۱، خروجی خلاصه‌ی گام ۲ (بی IP) و داوری گام ۳.

**نکن:**
- node، سرور یا Primary IP نساز و حذف نکن. node آزمایشی را هم مالک خودش از داشبورد بازنشسته میکند.
- `learned_server_limit` یا هیچ تنظیم دیگری را عوض نکن.
- `git push` نکن.
