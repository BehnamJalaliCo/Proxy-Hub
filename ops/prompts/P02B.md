# پرامپت ۲-ب: سنجش اصلاح دو باگ گزارش پرامپت ۲

> مالک فقط این را میچسباند: «`git pull` بزن، بعد فایل `ops/prompts/P02B.md` را بخوان و دقیق اجرا کن.»

همان قانون‌ها برقرار است: با مالک فارسی حرف بزن؛ هیچ رمزی را نشان نده؛ در ریپو commit یا push نکن.

**دو باگی که اصلاح شد (هر دو در محیط Claude ریپو بازتولید و سپس آزموده شد):**
1. `install.sh` شاخه را در `git clone` نمیداد. حالا با `--branch` clone میکند، و در هر اجرا `fetch` و `checkout` همان شاخه را میزند.
2. Redis پس از restart بالا نمیآمد (`/tmp` چسبنده است و `fs.protected_regular=2`). حالا فایل تنظیم در `/run/redis-conf` ساخته میشود و پیش از ساخت پاک میشود.
   - آزمون محلی: شروع، restart همه، دو بار restart خود Redis، و **restart کامل Docker daemon** (شبیه reboot): همه سبز.
   - این آزمون از این به بعد در CI هم هست.

کارها:
1. `git pull`. فایل‌های تغییرکرده را پیش از اجرا با root بخوان: `deploy/docker-compose.yml`، `deploy/install.sh` و `ops/scripts/stack_restart_test.sh`.
2. **اصلاح باگ ۱ با اجرای دوباره‌ی نصب:** `sudo bash deploy/install.sh ccr-4e0296ec-n0ez5a`. باید با exit 0 و «is healthy» تمام شود. سپس:
   - `sudo git -C /opt/proxy-hub log -1 --format=%H` باید با `git rev-parse origin/ccr-4e0296ec-n0ez5a` یکی باشد.
   - `cat /var/lib/proxy-hub/deployed_commit` باید همان commit باشد.
3. **سنجش باگ ۲ روی پنل واقعی** (project همان `proxyhub`؛ فقط restart، بدون build):
   1. `sudo docker compose -p proxyhub restart`، سپس `/healthz` حداکثر تا ۱۲۰ ثانیه سبز شود.
   2. `sudo docker compose -p proxyhub restart redis` و دوباره همان سنجش. این کار را **دو بار** بکن.
   3. **شبیه‌سازی reboot:** `sudo systemctl restart docker`، سپس `/healthz` حداکثر تا ۱۵۰ ثانیه سبز شود، و `sudo docker compose -p proxyhub ps` همه را بالا نشان دهد. (Claude Code و Remote Control داخل Docker نیستند و قطع نمیشوند.)
   4. رمز در argv نیست: `sudo docker compose -p proxyhub top redis | grep -c requirepass` باید `0` بدهد.
4. **گزارش پایانی** فارسی در یک بلوک برای Claude ریپو: نتیجه‌ی هر گام، با زمان سبز شدن `/healthz` در هر مورد. هر خطا با ۳۰ خط لاگ (بی رمز).

**نکن:** `ops/scripts/stack_restart_test.sh` را روی این سرور **اجرا نکن**. آن برای CI است و یک stack دیگر روی همان پورت ۸۰۰۰ میسازد. فایروال و SSH را هم تغییر نده (پرامپت ۳).
