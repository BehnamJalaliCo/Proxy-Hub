# پرامپت ۷: استقرار دور ۲ و روشن کردن سایت عامل‌های node (گام M2.1)

> مالک فقط این را میچسباند: «`git pull` بزن، بعد فایل `ops/prompts/P07.md` را بخوان و دقیق اجرا کن.» این پرامپت را پس از تمام شدن پرامپت ۶ اجرا کن.

قاعده‌های `ops/prompts/README.md` برقرار است: فارسی با مالک؛ هیچ رمز، توکن یا کلید خصوصی در گزارش نیاید؛ در ریپو commit یا push نکن؛ هر فایلی را که با root اجرا میشود، پیش از اجرا بخوان.

**چه آمده است (همه بی توکن و بی‌کار تا تصمیم بعدی مالک):**
- ربات تلگرام پنل: ثبت ربات، اتصال چت مالک با کد یک‌بارمصرف، ثبت کانال‌ها، صف پست بی‌حذف، و هشدارهای مالک. Alertmanager از این پس هر هشدار را به webhook داخلی پنل هم میفرستد.
- ساخت **یک** node آزمایشی به درخواست مالک، از ساخت تا بازنشستگی، و سایت جدای عامل‌ها روی `agent.beyra-ai.com` با mTLS اجباری. image پنل حالا فایل اجرایی عامل Go را هم میسازد و hash آن را با `node-image/versions.lock` میسنجد.
- Cloudflare (استخر دامنه و رکوردهای DNS خود پنل) و سنجش دسترسی از ایران (Globalping و check-host). چرخه‌ی خودکار دامنه (D35): سنجش فیلتر هر دامنه از ایران، بیرون بردن دامنه‌ی فیلترشده و جایگزینی با دامنه‌ی ذخیره، و پاک کردن آن از Cloudflare پس از ۲۴ ساعت (تا کلید توقف روشن است، پاک نمیشود).
- صفحه‌های داشبورد برای nodeها، تلگرام و Cloudflare.
- کلید توقف روشن است و ناوگان در حالت خشک قفل است. **هیچ سروری ساخته نمیشود، هیچ پستی فرستاده نمیشود و هیچ رکورد DNSی عوض نمیشود.**

کارها:
1. **پیش‌شرط:**
   - `sudo bash ops/scripts/deploy_status.sh` (از checkout خودت، پس از `git pull`) باید `RESULT: up to date` بدهد.
     - اگر «not deployed yet» گفت، تا ۱۵ دقیقه صبر کن. ساخت image این بار عامل Go را هم میسازد و طولانی‌تر است. پیشرفت: `sudo journalctl -u proxyhub-deployer.service -n 40 --no-pager`.
     - اگر «FAILED» گفت، ادامه نده و ۸۰ خط همان journal را گزارش بده.
   - `curl -s http://127.0.0.1:8000/healthz` باید `"status":"ok"` بدهد.
2. **سنجش نسخه‌ی تازه:**
   - `sudo docker compose -p proxyhub exec -T postgres psql -U proxyhub -d proxyhub -At -c "SELECT version_num FROM alembic_version"` باید `0010_domains` بدهد.
   - `sudo docker compose -p proxyhub logs worker 2>&1 | grep -o 'worker started with [0-9]* reconcilers' | tail -1` باید عدد **11** بدهد.
   - `sudo bash /opt/proxy-hub/deploy/monitoring/safe_logs.sh worker 300 | grep -c '"lvl":"ERROR"'` باید `0` بدهد. اگر نبود، همان ۳۰۰ خط را بخوان و فقط خط‌های ERROR را در گزارش بیاور.
   - `sudo docker compose -p proxyhub logs alertmanager 2>&1 | grep -c 'panel webhook: on'` باید دست‌کم `1` بدهد.
   - فایل عامل درون image: `sudo docker compose -p proxyhub exec -T api sha256sum /app/artifacts/proxyhub-agent` باید با مقدار `AGENT_SHA256` در `/opt/proxy-hub/node-image/versions.lock` یکی باشد.
   - هیچ nodeی نیست: `sudo docker compose -p proxyhub exec -T api python -m proxyhub.nodes list` باید `[]` بدهد.
3. **توقف تمیز worker** (اصلاح تازه؛ پیش‌تر Docker آن را با SIGKILL میکشت):
   - `W=$(sudo docker compose -p proxyhub ps -q worker)`
   - `sudo docker inspect -f '{{.Config.StopTimeout}} {{.State.StartedAt}}' $W`. عدد اول باید `30` باشد.
   - `time sudo docker stop $W` (بدون `-t`)، سپس `sudo docker inspect -f '{{.State.ExitCode}}' $W`. باید `0` بدهد، نه `137`. زمان توقف را هم گزارش کن.
   - `sudo docker start $W`. سپس `State.StartedAt` باید تازه باشد و `State.Running` باید `true` باشد.
4. **سنجش DNS نام عامل‌ها** (مالک رکورد را در Cloudflare ساخته است):
   - `ip -4 -o addr show scope global` و `getent ahostsv4 agent.beyra-ai.com | head -1` باید IP یکسان نشان دهند، یعنی IP خود این سرور.
   - اگر IP دیگری آمد (مثلاً یک IP Cloudflare)، یعنی ابر رکورد نارنجی است. ادامه نده و به مالک بگو در Cloudflare روی رکورد `agent` حالت «DNS only» (ابر خاکستری) را بزند. سپس ۵ دقیقه صبر کن و دوباره بسنج.
5. **روشن کردن سایت عامل‌ها:**
   - اول بخوان: `sudo grep -E '^(DEPLOY_BRANCH|PANEL_DOMAIN|AGENT_DOMAIN)=' /etc/proxy-hub/deploy.env`.
   - اگر `AGENT_DOMAIN` نبود: `echo 'AGENT_DOMAIN=agent.beyra-ai.com' | sudo tee -a /etc/proxy-hub/deploy.env >/dev/null`. اگر بود و مقدارش چیز دیگری بود، دست نزن و گزارش بده.
   - `sudo systemctl start proxyhub-deployer.service`. این فرمان تا پایان استقرار صبر میکند.
   - `sudo journalctl -u proxyhub-deployer.service -n 40 --no-pager` باید با `ok: ... is healthy` تمام شود. Caddy یک بار از نو بالا میآید: چند ثانیه پنل در دسترس نیست.
6. **گواهی‌ها:**
   - `sudo ls -l /var/lib/proxy-hub/caddy-agent/agent_ca.pem` باید حالت `-rw-r--r--` داشته باشد. این فایل گواهی **عمومی** CA است، نه کلید.
   - `sudo openssl x509 -noout -subject -in /var/lib/proxy-hub/caddy-agent/agent_ca.pem` باید `O = Proxy-Hub, CN = Proxy-Hub node agent CA` بدهد.
   - `echo | openssl s_client -connect agent.beyra-ai.com:443 -servername agent.beyra-ai.com 2>/dev/null | openssl x509 -noout -subject -issuer -enddate` باید گواهی Let's Encrypt برای `agent.beyra-ai.com` نشان دهد. اگر هنوز نبود، ۲ دقیقه صبر کن و دوباره بسنج. هر بار شمار `sudo docker compose -p proxyhub logs caddy --since 15m 2>&1 | grep -ci 'certificate obtained'` را هم بیاور.
7. **سنجش سایت عامل‌ها از بیرون** (همه با `curl` روی همین سرور):
   - a. `curl -s -o /dev/null -w '%{http_code}\n' https://agent.beyra-ai.com/` باید `404` بدهد.
   - b. `curl -s -w ' %{http_code}\n' https://agent.beyra-ai.com/agent/v1/desired` باید `{"error":"client_certificate_required"} 401` بدهد.
   - c. ثبت جعلی با سرآیند جعلی:
     ```
     curl -s -w ' %{http_code}\n' -X POST https://agent.beyra-ai.com/agent/v1/register -H 'Content-Type: application/json' -H 'X-ProxyHub-Agent-Proxy-Secret: forged' -d '{"token":"AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA","csr_pem":"x","agent_version":"0.1.0","telemt_version":null}'
     ```
     باید `401` (`invalid_token`) یا `422` بدهد. `403` یعنی Caddy سرآیند جعلی را جایگزین نکرده است. `503` یعنی api رمز `agent_proxy_secret` را ندارد. در هر دو حالت ادامه نده و گزارش بده.
   - d. `curl -s https://agent.beyra-ai.com/agent/v1/artifacts/proxyhub-agent | sha256sum` باید با `AGENT_SHA256` در `versions.lock` یکی باشد.
   - e. نام سخت‌گیرانه (SNI): هر دو باید `421` بدهند:
     - `curl -s -o /dev/null -w '%{http_code}\n' https://agent.beyra-ai.com/ -H 'Host: panel.beyra-ai.com'`
     - `curl -s -o /dev/null -w '%{http_code}\n' https://panel.beyra-ai.com/ -H 'Host: agent.beyra-ai.com'`
   - f. `curl -sI https://agent.beyra-ai.com/ | grep -ciE '^(server|via|alt-svc):'` باید `0` بدهد.
   - g. دامنه‌ی پنل مثل قبل است:
     - `curl -s -o /dev/null -w '%{http_code}\n' https://panel.beyra-ai.com/login` باید `200` بدهد.
     - این دو باید `404` بدهند:
       - `curl -s -o /dev/null -w '%{http_code}\n' https://panel.beyra-ai.com/agent/v1/register`
       - `curl -s -o /dev/null -w '%{http_code}\n' -X POST https://panel.beyra-ai.com/internal/alerts/alertmanager`
   - h. لاگ دسترسی هر دو سایت خاموش است: `sudo docker compose -p proxyhub logs caddy --since 10m 2>&1 | grep -c '"uri":'` باید `0` بدهد، با اینکه همین چند دقیقه پیش ده‌ها درخواست فرستادی.
8. **سنجش پایانی:** `sudo bash ops/scripts/deploy_status.sh` باید `RESULT: up to date` و health `ok` بدهد. `sudo bash /opt/proxy-hub/deploy/monitoring/verify_stack.sh proxyhub` هم باید سبز باشد.
9. **از مالک بخواه** (فقط نگاه، هیچ ورودی):
   - «در داشبورد، روی گوشی، صفحه‌های **nodeها**، **تلگرام** و **Cloudflare** را باز کنید (از منوی پایین یا «بیشتر»).
   - هر سه باید حالت خالی و آرام نشان دهند: هنوز رباتی، توکنی یا nodeی ثبت نشده است.
   - بگویید ظاهر و خوانایی‌شان روی گوشی چطور است.
   - **هنوز هیچ توکنی وارد نکنید و کلید توقف را خاموش نکنید.** وارد کردن توکن‌ها گام جدایی است.»
10. **گزارش پایانی** فارسی در یک بلوک برای Claude ریپو: نتیجه‌ی هر گام، و خروجی گام‌های ۲، ۳، ۶ و ۷ (بی کوکی و بی رمز). برای هر خطا ۳۰ خط لاگ، فقط با `sudo bash /opt/proxy-hub/deploy/monitoring/safe_logs.sh <service> 30`. نظر مالک درباره‌ی صفحه‌ها را هم بیاور.

**نکن:**
- هیچ توکنی (ربات، Cloudflare، هتزنر) را از مالک نخواه و در داشبورد وارد نکن.
- کلید توقف، سقف بودجه و سقف node را عوض نکن. node آزمایشی نساز (`test-node` را اجرا نکن).
- pytest را در `/opt/proxy-hub` اجرا نکن. آن checkout مال deployer است.
- `git fetch` یا `git pull` در `/opt/proxy-hub` نزن.
