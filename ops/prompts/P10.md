# پرامپت ۱۰: اولین node آزمایشی واقعی، از ساخت تا حذف

> مالک این را میچسباند: «`git pull` بزن (روی `main`)، بعد فایل `ops/prompts/P10.md` را بخوان و دقیق اجرا کن.» مالک توکن حساب جدای هتزنر nodeها را در داشبورد ثبت کرده است.

قاعده‌های `ops/prompts/README.md` برقرار است: فارسی با مالک؛ هیچ رمز، توکن یا کلید خصوصی در گزارش نیاید؛ در ریپو commit یا push نکن؛ هر فایلی را که با root اجرا میشود، پیش از اجرا بخوان.

**هدف:** یک سرور واقعی در هتزنر از راه پنل ساخته شود، عامل آن با mTLS ثبت شود و گزارش بدهد، و بعد از راه همان قفل‌های پنل حذف شود. هزینه حدود ۲ سنت است. **فقط یک سرور.** پنل خودش آن را میسازد و حذف میکند. **هیچ‌کس دستی در کنسول هتزنر سرور نمیسازد و پاک نمیکند.**

فرمان پایه:
`C="sudo docker compose -p proxyhub exec -T api python -m proxyhub.nodes"`

کارها:
1. **پیش‌شرط:**
   - `sudo bash ops/scripts/deploy_status.sh` باید `branch: main` و `RESULT: up to date` بدهد.
   - `$C servers`: حساب nodeها باید دیده شود با `"others": 0` (هیچ سرور بیگانه‌ای در project نیست). اگر `others` بیشتر از ۰ بود، **ادامه نده** و به مالک بگو (قانون ۴ `CLAUDE.md`).
   - `$C list` باید `[]` بدهد.
2. **از مالک بخواه** (در داشبورد، صفحه‌ی **تنظیمات**):
   - «سقف بودجه‌ی ماه را **150** یورو و سقف تعداد node را فعلاً **1** بگذارید و ذخیره کنید.»
   - «بعد از نوار قرمز بالای صفحه (مدیریت)، **کلید توقف را خاموش کنید.**»
   - صبر کن تا مالک بگوید انجام شد.
3. **ساخت** (مالک در داشبورد، صفحه‌ی **nodeها**):
   - «دکمه‌ی "ساخت node آزمایشی" را بزنید، تیک "میدانم…" را بزنید و تأیید کنید.»
   - اگر پنل رد کرد، دلیل‌های فارسی را از مالک بگیر و گزارش بده. قفلی را دور نزن.
   - `$C list`: شناسه‌ی node (`ID`) را بردار.
4. **صبر تا آماده شدن** (حدود ۳ تا ۱۰ دقیقه):
   - `$C wait <ID> ready --timeout 1500`
   - اگر نرسید: `$C events <ID>` را کامل گزارش بده (به‌ویژه `create_failed`، `boot_timeout` یا رفتن به `unhealthy`). سپس به گام ۶ برو تا node حذف شود.
5. **سنجش‌ها:**
   - `$C list` باید این‌ها را نشان دهد: `agent.registered` برابر `true`، `telemt_version` برابر `3.5.16`، و یک `ipv4`.
   - `$C servers` باید **دقیقاً یک** سرور ما را با این برچسب‌ها نشان دهد: `managed-by=proxy-hub`، `role=node`، `purpose=test` و `node-id=<ID>`. `others` باید ۰ بماند.
   - `curl -s -o /dev/null -w '%{http_code}\n' --max-time 5 http://<ipv4>:22` باید شکست بخورد یا `000` بدهد (SSH روی node بسته است).
   - از مالک بخواه صفحه‌ی **nodeها** را ببیند و بگوید node در وضعیت «آماده» دیده میشود.
6. **حذف** (مالک در داشبورد):
   - «روی همان node، "بازنشسته کردن" را بزنید و تأیید کنید.»
   - `$C wait <ID> deleted --timeout 600`
   - `$C servers` نباید هیچ سرور `purpose=test` نشان دهد. اگر هنوز بود، یک دقیقه بعد دوباره بسنج؛ حذف در هتزنر ناهمزمان است.
   - `$C events <ID>` باید این مراحل را داشته باشد: `server_created`، `agent_registered`، رسیدن به `ready`، سپس `retiring`، `server_deleted` و `deleted`.
7. **بستن:** از مالک بخواه **کلید توقف را دوباره روشن کند.** سپس بسنج:
   - `sudo docker compose -p proxyhub exec -T postgres psql -U proxyhub -d proxyhub -At -c "SELECT value->>'kill_switch' FROM settings WHERE key='fleet'"` باید `true` بدهد. اگر کلید تنظیمات جای دیگری است، از روی کد (`proxyhub/fleet/settings_store.py`) پیدا کن.
8. **گزارش پایانی** فارسی در یک بلوک برای Claude ریپو:
   - زمان هر مرحله (درخواست، ساخت، ثبت عامل، آماده، حذف)؛
   - خروجی `list`، `servers` و `events` (بی هیچ رمز)؛
   - هر خطا با ۳۰ خط لاگ، فقط با `safe_logs.sh`.

**نکن:**
- کلید توقف را خودت عوض نکن؛ فقط مالک از داشبورد.
- بیش از یک node نساز. `test-node` را دوباره نزن، مگر node قبلی `deleted` شده باشد و مالک بخواهد.
- در کنسول هتزنر یا با `hcloud` هیچ سروری را دستی نساز یا پاک نکن. حذف فقط از راه پنل است.
- `git push` نکن. هیچ شاخه یا ریپویی نساز یا پاک نکن.
