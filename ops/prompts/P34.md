0. **استقرار:**
   - `deploy_status.sh` باید `RESULT: up to date` بدهد (commit ادغام PR ۴۶ یا تازه‌تر).
   - `Q "SELECT version_num FROM alembic_version"` باید `0036_proxies_octets_total` بدهد.
   - `Q "SELECT count(*) FROM admin_devices"` (جدول باید باشد؛ عدد مهم نیست).
   - شمار خطای worker در ۳۰ دقیقه‌ی پس از استقرار باید ۰ باشد.
   - `cmp /usr/local/sbin/proxyhub-deploy deploy/deployer.sh && echo same`: deployer نصب‌شده باید همان نسخه‌ی repo باشد.
   - `sudo docker images proxyhub/panel --format '{{.Tag}}' | wc -l`: پس از استقرار بعدی باید ۲ یا کمتر شود (این بار هنوز ممکن است بیشتر باشد).
1. **چرخه‌ها و هشدارها:**
   - `curl -s http://127.0.0.1:8000/internal/metrics` از درون شبکه‌ی compose (همان روشی که پیش‌تر برای metrics به کار بردی): برای هر چرخه، سن آخرین پاس موفق را با بازه‌اش مقایسه کن. هیچ چرخه‌ای نباید بیش از ۳ برابر بازه‌اش عقب باشد.
   - در Alertmanager یا Prometheus: `ReconcilerStalled`، `DeployFailed` و `DeployRollbackFailed` نباید firing باشند.
   - `Q "SELECT at, action FROM actions_log WHERE action = 'telegram.channel_refreshed' ORDER BY id DESC LIMIT 3"` (چرخه‌ی تازه‌ی خواندن روزانه‌ی کانال‌ها؛ تا ۲۴ ساعت ممکن است خالی باشد).
2. **ناوگان:**
   - `Q "SELECT action, allowed, reasons->'reasons' FROM actions_log WHERE at > now() - interval '30 minutes' AND action IN ('node_request','node_create','node_create_failed') ORDER BY id DESC LIMIT 10"`.
   - در برنامه‌ی آخر ناوگان (`fleet_plans`) دلیل `prices_stale` نباید باشد مگر قیمت‌های حساب فعال واقعاً کهنه باشند.
   - `Q "SELECT n.slot, n.location, n.state, a.agent_version FROM nodes n LEFT JOIN agent_nodes a ON a.node_id = n.id WHERE n.state <> 'deleted' ORDER BY n.slot"`. سرور تازه‌ای که از این پس ساخته شود باید عامل `0.5.1` داشته باشد.
