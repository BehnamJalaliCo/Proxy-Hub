# پرامپت ۱۱: دور ۳ روی سرور، و یک node آزمایشی با MTProto، ریلیتی، اسپانسر و پست

> مالک این را میچسباند: «`git pull` بزن (روی `main`)، بعد فایل `ops/prompts/P11.md` را بخوان و دقیق اجرا کن.» Claude ریپو PR دور ۳ را در `main` ادغام کرده است.

قاعده‌های `ops/prompts/README.md` برقرار است:
- با مالک فارسی حرف بزن.
- هیچ رمز، توکن، کلید خصوصی یا **لینک پروکسی** در گزارش نیاید، چون لینک secret دارد. فقط `host:port` و نوع لینک را گزارش کن.
- در ریپو commit یا push نکن.
- هر فایلی را که با root اجرا میشود، پیش از اجرا بخوان.

**هدف:** همه‌ی چیزهای دور ۳ روی **یک node آزمایشی واقعی** و **فقط کانال آزمایشی** سنجیده شوند:
- پروکسی MTProto (Telemt)؛
- کانفیگ ریلیتی (Xray)؛
- ثبت خودکار در ‎@MTProxybot‎ با حساب دوم؛
- پست خودکار؛
- صفحه‌ی «آمار».

هزینه چند سنت است. **فقط یک سرور.** هیچ‌چیز به کانال اصلی نمیرود.

فرمان‌های پایه:
- `C="sudo docker compose -p proxyhub exec -T api python -m proxyhub.nodes"`
- `Q() { sudo docker compose -p proxyhub exec -T postgres psql -U proxyhub -d proxyhub -At -c "$1"; }`
- `L() { sudo bash /opt/proxy-hub/deploy/monitoring/safe_logs.sh "$1" "${2:-60}"; }`

کارها:

1. **پیش‌شرط** (اگر یکی نشد، ادامه نده و گزارش بده):
   - `sudo bash ops/scripts/deploy_status.sh` باید `branch: main` و `RESULT: up to date` بدهد. آخرین commit باید ادغام PR دور ۳ باشد.
   - `Q "SELECT version_num FROM alembic_version"` باید `0017_merge` بدهد.
   - `curl -s http://127.0.0.1:8000/healthz` باید `"status":"ok"` بدهد.
   - `sudo bash /opt/proxy-hub/deploy/monitoring/verify_stack.sh proxyhub` باید `ALL PASS` بدهد.
   - `L worker 200 | grep -c "worker started with 19 reconcilers"` باید دست‌کم `1` بدهد.
   - `L worker 300 | grep -ciE "traceback|failed; retrying"` را گزارش کن. اگر بیشتر از ۰ بود، ۳۰ خط دور آن را هم بیاور.
   - `$C servers`: باید `"others": 0` بدهد، وگرنه **ادامه نده** (قانون ۴). `$C list` باید `[]` بدهد.
   - `Q "SELECT value->>'kill_switch', value->>'dry_run', value->>'node_cap_total' FROM settings WHERE key='fleet'"` را گزارش کن. انتظار: `true|true|1`.
2. **صفحه‌های تازه** را از مالک بپرس. باید در منو باشند و بی خطا باز شوند:
   - «آمار»
   - «پروکسی‌های MTProto»
   - «اسپانسر»
   - «محتوا و انتشار»
   - «Reality»
3. **ساخت node آزمایشی** (مالک در داشبورد):
   - «کلید توقف را خاموش کنید.» سقف node باید ۱ بماند و حالت خشک روشن بماند.
   - در صفحه‌ی nodeها «ساخت node آزمایشی» را بزنید.
   - `$C list` را اجرا کن و شناسه‌ی node را `ID` بنام.
   - `$C wait <ID> ready --timeout 1500`. اگر نرسید، `$C events <ID>` را گزارش کن و به گام ۹ برو.
4. **MTProto:**
   - `Q "SELECT c.ports, c.tls_domain, c.mode_tls FROM telemt_node_configs c WHERE c.node_id='<ID>'"` باید `{8443}|www.microsoft.com|t` بدهد.
   - تا ۲ دقیقه: `Q "SELECT live_at IS NOT NULL FROM mtproto_proxies WHERE node_id='<ID>'"` باید `t` بدهد.
   - `timeout 5 bash -c '</dev/tcp/<ipv4>/8443' && echo open` باید `open` بدهد.
   - `curl -sS -o /dev/null -w '%{http_code} %{ssl_verify_result}\n' --resolve www.microsoft.com:8443:<ipv4> https://www.microsoft.com:8443/` باید یک کد HTTP و `0` بدهد.
   - **از مالک بخواه، روی گوشی و با اینترنت ایران و بی VPN:**
     - «در صفحه‌ی پروکسی‌های MTProto، "کپی لینک" را بزنید، در تلگرام باز کنید و Connect را بزنید. وصل شد؟»
     - اگر وصل شد: «آیا کانال ‎@ipoxxo‎ بالای فهرست چت‌ها به‌عنوان اسپانسر دیده میشود؟» این تا یک ساعت پس از گام ۶ ممکن است طول بکشد.
     - پاسخ‌ها و نام اپراتور مالک (همراه اول، ایرانسل…) را گزارش کن.
5. **ریلیتی:**
   - تا ۳ دقیقه: `Q "SELECT up, target_ok, checked_target, apply_error FROM reality_node_status WHERE node_id='<ID>'"` باید `t|t|dl.google.com:443|` بدهد.
   - `Q "SELECT status, expires_at > now() FROM reality_configs WHERE node_id='<ID>' ORDER BY id"` باید دست‌کم یک `active|t` بدهد.
   - `timeout 5 bash -c '</dev/tcp/<ipv4>/443' && echo open` باید `open` بدهد.
   - **از مالک بخواه، با اینترنت ایران و بی VPN:**
     - «در صفحه‌ی Reality لینک کانفیگ را کپی کنید و در v2rayNG، Hiddify یا Streisand وارد کنید. وصل شد و سایت باز شد؟»
     - سپس بسنج که `Q "SELECT used_bytes FROM reality_configs WHERE node_id='<ID>'"` بیشتر از صفر شده باشد.
6. **اسپانسر (‎@MTProxybot‎ با حساب دوم):**
   - صفحه‌ی «تلگرام» باید حساب دوم را «وصل» نشان دهد. اگر نشان نداد، از مالک بخواه دوباره وصلش کند.
   - تا ۱۵ دقیقه: `Q "SELECT action, allowed FROM actions_log WHERE action LIKE 'sponsor%' ORDER BY id DESC LIMIT 25"`. باید `registered` و بعد `tag_applied` دیده شوند، و در گذر بعدی `promotion_set`.
   - `Q "SELECT state, sponsor_channel, ad_tag IS NOT NULL FROM mtproxy_registrations"` باید `registered|ipoxxo|t` بدهد. خود tag را نیاور.
   - `Q "SELECT name, ad_tag IS NOT NULL, registration_id IS NOT NULL FROM telemt_users WHERE node_id='<ID>'"` باید `…|t|t` بدهد.
   - اگر جریان گیر کرد، صفحه‌ی «اسپانسر» متن ربات را نشان میدهد. آن متن را (بی secret) گزارش کن و «ثبت دوباره» را **نزن**. Claude ریپو تصمیم میگیرد.
7. **پست در کانال آزمایشی:**
   - صفحه‌ی «محتوا و انتشار» باید «انتشار در کانال اصلی: خاموش» نشان دهد. **روشنش نکن.**
   - تا ساعت پست بعدی (برنامه از ۰۸:۰۰ تا ۲۴:۰۰ تهران است، هر ۱ تا ۲ ساعت): `Q "SELECT id, role, created_at FROM posts ORDER BY id DESC LIMIT 3"` باید پستی با `role` = `test` نشان دهد.
   - از مالک بپرس:
     - «پست در کانال آزمایشی آمد؟ متن محتوا، پروکسی آزمایشی و ریلیتی در آن هست؟»
     - «در صفحه‌ی "محتوا و انتشار"، پیش‌نمایش کانال اصلی هیچ لینکی از سرور آزمایشی نشان نمیدهد؟»
8. **آمار:**
   - حدود ۱۵ دقیقه پس از آماده شدن node: `Q "SELECT count(*) FROM analytics_node_samples"` باید بیشتر از ۰ باشد.
   - `Q "SELECT count(*) FROM analytics_channel_samples"` را گزارش کن.
   - از مالک بپرس: «صفحه‌ی آمار، ترافیک و هزینه‌ی سرور آزمایشی را با جمله‌ی فارسی نشان میدهد؟»
9. **بستن** (مالک در داشبورد):
   - «روی node آزمایشی "بازنشسته کردن" را بزنید.»
   - تا ۳۰ ثانیه: `Q "SELECT enabled FROM telemt_users WHERE node_id='<ID>'"` باید `f` بدهد.
   - `$C wait <ID> deleted --timeout 600`
   - `$C servers` نباید سرور `purpose=test` نشان دهد.
   - پست کانال آزمایشی باید تا حدود ۴۰ دقیقه ویرایش شود و کنار آن لینک‌ها علامت «تمام شد» یا «در دسترس نیست» بیاید. **پست نباید حذف شود.**
   - از مالک بخواه **کلید توقف را دوباره روشن کند.** سپس بسنج: `Q "SELECT value->>'kill_switch' FROM settings WHERE key='fleet'"` باید `true` بدهد.
10. **نشت:**
    - `sudo docker compose -p proxyhub logs --no-color api worker 2>&1 | grep -cE 'secret=|ee[0-9a-f]{32}|dd[0-9a-f]{32}|vless://'` باید `0` بدهد.
    - فقط عدد را گزارش کن.
11. **گزارش پایانی** فارسی در یک بلوک برای Claude ریپو:
    - نتیجه‌ی هر گام؛
    - خروجی SQLها (بی secret، tag یا لینک)؛
    - پاسخ‌های مالک: وصل شدن MTProto و ریلیتی از ایران و نام اپراتور، دیده شدن اسپانسر، پست آزمایشی؛
    - زمان هر مرحله؛
    - برای هر خطا ۳۰ خط لاگ، فقط با `safe_logs.sh`.

**نکن:**
- کلید توقف، حالت خشک، سقف بودجه و سقف node را خودت عوض نکن. فقط مالک، از داشبورد.
- «انتشار در کانال اصلی» را روشن نکن. چیزی به کانال اصلی نفرست. هیچ پیامی را حذف نکن.
- بیش از یک node نساز. در کنسول هتزنر دستی چیزی نساز و پاک نکن.
- تنظیمات MTProto و Reality (پورت، دامنه و سایت هدف) را عوض نکن.
- `git push` نکن. هیچ شاخه یا ریپویی نساز یا پاک نکن.
