# پرامپت ۲۳: خواندن کانال‌های منبع با حساب دوم (D55)

> مالک این را میچسباند: «`git pull` بزن (روی `main`)، بعد فایل `ops/prompts/P23.md` را بخوان و تا رسیدن به نتیجه، خودت اجرا کن.»

قاعده‌های `ops/prompts/README.md` برقرار است:
- فارسی و **کوتاه** با مالک.
- هیچ رمز، کلید، access_hash، session، متن کامل یک خبر یا لینک کامل پروکسی در گزارش نیاید.
- commit یا push نکن.

فرمان‌ها:
- `Q() { sudo docker compose -p proxyhub exec -T postgres psql -U proxyhub -d proxyhub -At -c "$1"; }`
- `W() { sudo docker compose -p proxyhub logs --since "$1" worker 2>&1 | grep -E "content|operator|sponsor" | tail -n 40; }`

**چه عوض شد (این PR):**
- **D55:** منبع تلگرام حالا با **حساب دوم** خوانده میشود، همان حسابی که با ایموجی Premium پست میگذارد (D38)، نه با `t.me/s`. پس کانال‌هایی مثل ‎@iMTProto‎ هم که پیش‌نمایش وب را خاموش کرده‌اند، خوانده میشوند.
  - حساب فقط **میخواند**: نام منبع را پیدا میکند، ۲۰ پست آخر را میخواند، یک پست را دوباره میخواند و عکس یا ویدیو یا پیش‌نمایش ویدیوی همان پست را دانلود میکند. **عضو کانال نمیشود**، چیزی را «خوانده‌شده» نمیکند، فوروارد نمیکند و هیچ‌جا نمینویسد. این در allowlist خود `proxyhub/mtproxy/userclient.py` قفل است (`SOURCE_READ_REQUESTS`).
  - هر منبع تلگرام هر **۱۰ دقیقه** خوانده میشود (نه ۵). شناسه‌ی کانال یک بار پیدا میشود و در `settings` با کلید `content.tg_channels` میماند، تا هر بار `resolveUsername` نزند (هر ۷ روز دوباره).
  - همه‌چیز زیر همان قفل حساب است. اگر پست‌گذار یا اسپانسر حساب را در دست داشته باشند، منبع تا دور بعد صبر میکند.
  - اگر تلگرام «صبر کن» (flood wait) بدهد، همه‌ی خواندن‌ها و دانلودهای حساب تا پایان آن مدت میایستند.
  - اگر حساب وصل نباشد، کلید توقف روشن باشد یا گاوصندوق خوانده نشود، مثل قبل پیش‌نمایش وب خوانده میشود.
  - رسانه با نشانی `tgmsg:<نام>/<شماره>` نگه داشته میشود، نه URL. پیش از دانلود، اندازه‌ای که تلگرام اعلام میکند سنجیده میشود: عکس ۵ مگابایت، ویدیو ۲۰ مگابایت و فقط MP4.
- `deploy/claude-bridge/install.sh` حالا تا ساخته شدن سوکت صبر میکند (نکته‌ی P22). خود پل عوض نشده است.
- مهاجرت تازه نیست.

0. **پیش‌شرط:**
   - `deploy_status.sh` باید `RESULT: up to date` بدهد.
   - `Q "SELECT version_num FROM alembic_version"` باید `0028_content_qc` بدهد.
   - شمار خطای worker باید ۰ باشد.
   - حساب دوم وصل و کلید توقف خاموش باشد:
     - `Q "SELECT value->>'state' FROM settings WHERE key='mtproxy.account'"` باید `connected` بدهد؛
     - `Q "SELECT value->>'kill_switch' FROM settings WHERE key='fleet'"` باید `false` بدهد.
   - اگر یکی نبود، **همین‌جا بایست و گزارش بده.** خودت عوضش نکن.
1. **خواندن ‎@iMTProto‎** (منبع شماره‌ی ۱ از P22):
   - همان کار دکمه‌ی «الان بخوان» داشبورد: `Q "UPDATE content_sources SET next_fetch_at = now() WHERE kind = 'telegram' AND enabled RETURNING id, ref"`.
   - ۲ دقیقه صبر کن، بعد:
     - `Q "SELECT id, ref, enabled, last_error, last_count, failures, round(extract(epoch FROM next_fetch_at - last_fetch_at) / 60) FROM content_sources ORDER BY id"`. انتظار: `last_error` خالی، `last_count` بیشتر از ۰، و فاصله‌ی ۱۰ دقیقه.
     - `W 5m`. انتظار: خطی مثل `content: 1 source(s) read (1=ok:N)`، بی `Traceback`.
     - `Q "SELECT key, (SELECT count(*) FROM jsonb_object_keys(value)) FROM settings WHERE key = 'content.tg_channels'"`. انتظار: یک ردیف با ۱. **مقدارش را نشان نده.**
     - `Q "SELECT count(*), count(*) FILTER (WHERE media_kind = 'photo'), count(*) FILTER (WHERE media_kind = 'video'), count(*) FILTER (WHERE media_url LIKE 'tgmsg:%') FROM content_candidates WHERE source_id = 1"`.
   - اگر `last_error` چیزی داشت، آن کد و ۳۰ خط `W 10m` را بیاور و همین‌جا بایست.
2. **رسانه** (۳ تا ۵ دقیقه‌ی دیگر):
   - `Q "SELECT media_kind, media_state, media_error, count(*) FROM content_candidates WHERE source_id = 1 GROUP BY 1, 2, 3 ORDER BY 1, 2"`. انتظار: عکس‌ها `ready`. ویدیوها `waiting` تا ناظر یا تأیید آن‌ها را بخواهد. پیش‌نمایش ویدیو جدا در `content_media` با نقش `thumb` میآید.
   - `Q "SELECT m.role, m.mime, count(*), max(m.size) FROM content_media m JOIN content_candidates c ON c.id = m.candidate_id WHERE c.source_id = 1 GROUP BY 1, 2"`.
3. **ناظر** (تا ۱۵ دقیقه):
   - `Q "SELECT status, count(*) FROM content_candidates WHERE source_id = 1 GROUP BY 1"`.
   - `Q "SELECT enabled, disabled_reason FROM content_sources WHERE id = 1"`.
   - ‎@iMTProto‎ خودش کانال پروکسی است. بیشتر پست‌هایش لینک پروکسی و تبلیغ‌اند. **انتظار:** ناظر بیشتر آن‌ها را رد میکند و ممکن است منبع را خودکار خاموش کند. این رفتار درست است، نه خطا. فقط گزارش کن.
4. **حساب دوم سالم ماند:**
   - `W 30m | grep -E "asked the account to wait|flood"` باید **خالی** باشد.
   - پست‌گذار هنوز کار میکند: `Q "SELECT id, created_at, edits, edit_failures FROM posts ORDER BY id DESC LIMIT 3"`. پست تازه‌ای که پس از استقرار این PR رفته باشد، یعنی قفل حساب گیر نکرده است. اگر تا ۳۰ دقیقه پستی نرفت، فقط گزارش کن.
   - اسپانسر: `Q "SELECT action, at FROM actions_log WHERE action LIKE 'sponsor.%' ORDER BY id DESC LIMIT 3"`. فقط نام کار و زمان را بیاور.
   - **از مالک بخواه** در حساب دوم، فهرست چت‌ها را نگاه کند: ‎@iMTProto‎ **نباید** آنجا باشد، چون حساب عضو نمیشود.
5. **منبع‌های مالک:**
