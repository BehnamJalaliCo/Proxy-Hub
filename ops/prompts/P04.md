# پرامپت ۴: HTTPS روی panel.beyra-ai.com

> مالک فقط این را میچسباند: «`git pull` بزن، بعد فایل `ops/prompts/P04.md` را بخوان و دقیق اجرا کن.»

قاعده‌های `ops/prompts/README.md` برقرار است.

**وضعیت DNS (وارسی Claude ریپو):**
- `panel.beyra-ai.com` رکورد A دارد که **مستقیم** (بدون پروکسی Cloudflare) به IP همین سرور میرود.
- nameserverها مال Cloudflare است. رکورد CAA ندارد، پس Let's Encrypt مجاز است.

کارها:
1. `git pull`. `deploy/Caddyfile` و `deploy/deployer.sh` را پیش از اجرا بخوان. تغییرها:
   - `/healthz` و `/livez` از بیرون بسته‌اند.
   - deployer تغییر `deploy.env` را هم میبیند و اعمال میکند.
2. **سنجش DNS از خود سرور:** `getent hosts panel.beyra-ai.com` باید همان IP عمومی سرور باشد (`curl -4 -s https://api.ipify.org`). اگر یکی نبود، **ادامه نده** و گزارش بده.
3. **تنظیم دامنه:** در `/etc/proxy-hub/deploy.env` خط `PANEL_DOMAIN=` را به `PANEL_DOMAIN=panel.beyra-ai.com` تغییر بده (با `sudo sed -i`؛ بقیه‌ی فایل دست نخورد). سپس `sudo /usr/local/sbin/proxyhub-deploy` را اجرا کن. باید ببیند تنظیم عوض شده و Caddy را بالا بیاورد.
4. **سنجش واقعی HTTPS (از خود سرور):**
   - `sudo docker compose -p proxyhub ps`: سرویس `caddy` بالاست.
   - `curl -sI https://panel.beyra-ai.com/`: پاسخ HTTP میآید و **خطای گواهی ندارد** (`404` فعلاً طبیعی است؛ داشبورد هنوز نیست).
   - گواهی: `echo | openssl s_client -connect panel.beyra-ai.com:443 -servername panel.beyra-ai.com 2>/dev/null | openssl x509 -noout -issuer -subject -enddate`. صادرکننده Let's Encrypt (یا ZeroSSL) باشد و subject همان دامنه.
   - `curl -sI http://panel.beyra-ai.com/`: به `https://` redirect شود.
   - `curl -s -o /dev/null -w "%{http_code}" https://panel.beyra-ai.com/healthz` باید `404` بدهد (از بیرون بسته است). ولی `curl -s http://127.0.0.1:8000/healthz` هنوز `"status":"ok"` بدهد.
   - سرآیندهای امنیتی در پاسخ: `Strict-Transport-Security`، `X-Content-Type-Options` و `X-Frame-Options`.
5. **پایداری:** `sudo docker compose -p proxyhub restart caddy`، سپس `State.StartedAt` پیش و پس را بسنج و HTTPS را دوباره امتحان کن. گواهی باید از volume بماند و دوباره گرفته نشود. این را در لاگ caddy ببین، بی رمز.
6. **لاگ ufw خاموش** (پیشنهاد پذیرفته‌شده): `sudo ufw logging off` و سنجش با `sudo ufw status verbose`.
7. **گزارش پایانی** فارسی در یک بلوک: نتیجه‌ی هر گام، issuer و تاریخ انقضای گواهی، و هر خطا با ۳۰ خط لاگ caddy (بی رمز).

**نکن:** رکوردهای Cloudflare را تغییر نده. ابر نارنجی (پروکسی) را روشن نکن؛ آن تصمیم جداست.
