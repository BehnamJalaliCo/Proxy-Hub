# پرامپت ۲۸: بی پست آموزشی (D58) و خبر کانال‌های پروکسی بی پروکسی‌شان (D59)

> مالک این را میچسباند: «`git pull` بزن (روی `main`)، بعد فایل `ops/prompts/P28.md` را بخوان و تا رسیدن به نتیجه، خودت اجرا کن.»

قاعده‌های `ops/prompts/README.md` برقرار است:
- فارسی و **کوتاه** با مالک.
- هیچ رمز، کلید، متن کامل خبر یا لینک کامل پروکسی در گزارش نیاید.
- commit یا push نکن.

فرمان‌ها:
- `Q() { sudo docker compose -p proxyhub exec -T postgres psql -U proxyhub -d proxyhub -At -c "$1"; }`
- `W() { sudo docker compose -p proxyhub logs --since "$1" worker 2>&1 | grep -E "content|publisher|Traceback" | tail -n 40; }`

**این پرامپت چیزی را عوض نمیکند.** فقط میسنجد و گزارش میدهد.

**چه عوض شد (PR ۳۴):**
- **D58:** ۳۶ پست آموزشی پیش‌ساخته‌ی پنل (`content_items` با `origin = 'seed'`) با مهاجرت `0030_retire_seed_content` بازنشسته شدند.
  - اگر برای نوبتی خبری تأیید نشد: اول نوشته‌ی تأییدشده‌ی خود مالک، وگرنه پست **فقط با پروکسی‌ها**، با تیتر «📡 پروکسی‌ها و کانفیگ‌های تازه».
  - ناظر برای هر نوبت تا **۶** خبر را بررسی میکند (`per_slot`، پیش‌فرض تازه).
- **D59:** کانال‌های پروکسی (imtproto، mtpproxyirani، proxydaemi) منبع میمانند.
  - پستی که فقط تبلیغ پروکسی است، ذخیره نمیشود.
  - از خبرهایشان خط‌ها و لینک‌های پروکسی پاک میشود.

0. **پیش‌شرط:**
   - `deploy_status.sh` باید `RESULT: up to date` بدهد.
   - `Q "SELECT version_num FROM alembic_version"` باید `0030_retire_seed_content` بدهد.
   - شمار خطای worker باید ۰ باشد.
1. **بانک محتوا:** `Q "SELECT origin, status, count(*) FROM content_items GROUP BY 1, 2 ORDER BY 1, 2"`. انتظار: همه‌ی ردیف‌های `seed` در حالت `retired` (۳۶).
2. **تنظیم ناظر:** `Q "SELECT value->>'per_slot', value->>'bridge_daily_cap' FROM settings WHERE key = 'content.qc'"`. اگر ردیفی نیست، پیش‌فرض‌ها برقرارند: ۶ و ۸۰. اگر `per_slot` ذخیره‌شده‌ای کمتر از ۶ دیدی، فقط گزارش کن.
3. **سه منبع پروکسی:**
   - `Q "SELECT ref, enabled, disabled_reason, disabled_at FROM content_sources WHERE ref IN ('imtproto', 'mtpproxyirani', 'proxydaemi') ORDER BY ref"`.
   - اگر یکی `enabled = f` با `qc_rejects` است، **به مالک بگو** از صفحه‌ی «منبع‌های محتوا» روشنش کند. روشن کردن کارنامه‌ی منبع را از نو شروع میکند. خودت روشنش نکن.
4. **پس از استقرار، تا دو نوبت پست بعدی** (حداکثر ۲ ساعت؛ هر ۳۰ دقیقه یک بار بسنج، نه بیشتر):
   - `Q "SELECT id, created_at, content_candidate_id IS NOT NULL, content_item_id IS NOT NULL, media_kind FROM posts WHERE role = 'main' ORDER BY id DESC LIMIT 5"`. انتظار: ستون سوم `t` (خبر منبع)، یا هر دو ستون `f` (فقط پروکسی). ستون چهارم (`content_item_id`) برای پست‌های تازه نباید `t` باشد، مگر نوشته‌ی خود مالک.
   - `Q "SELECT s.ref, count(*) FILTER (WHERE c.qc_decision = 'approve'), count(*) FILTER (WHERE c.qc_decision = 'reject') FROM content_candidates c JOIN content_sources s ON s.id = c.source_id WHERE c.qc_at > now() - interval '3 hours' GROUP BY 1 ORDER BY 1"`.
   - `Q "SELECT s.ref, count(*) FROM content_candidates c JOIN content_sources s ON s.id = c.source_id WHERE c.created_at > now() - interval '3 hours' AND s.ref IN ('imtproto', 'mtpproxyirani', 'proxydaemi') GROUP BY 1"`. نامزدهای تازه‌ی این سه منبع: فقط خبرها، بی تبلیغ پروکسی.
   - `W 2h | grep -E "Traceback|error"`، که باید خالی باشد.
5. **گزارش پایانی** در یک بلوک کوتاه برای Claude ریپو: ردیف‌های گام‌های ۱ تا ۴، و چند پست از نوبت‌های پس از استقرار خبر بودند، چند تا فقط پروکسی، و چند تا آموزشی (باید ۰ باشد).
