**چه عوض شد (این PR):**
- **D52:** محتوا بی تأیید مالک میرود، ولی فقط پس از کنترل کیفیت خودکار:
  - **ناظر** (چرخه‌ی `content_qc` در worker) پیش از هر پست، بهترین نامزدها را به ترتیب امتیاز به Claude میدهد: بازدید در ساعت، تازگی و شمار منبع‌هایی که همان خبر را دارند. برای هر پست حداکثر ۳ نامزد.
  - **Claude** عکس و متن را میبیند. ویدیو را کامل میبیند: worker ویدیو را پیش از بررسی دانلود میکند و با `ffmpeg` (داخل image پنل) ۶ فریم از سراسر آن برمیدارد. همه‌ی فریم‌ها به ترتیب در یک بررسی میروند. ویدیوی بلندتر از ۳ دقیقه یا ناخوانا بی Claude رد میشود. Claude تصمیم، دلیل، دسته، پرچم‌های ایمنی، تیتر و متن کوتاه فارسی را در JSON برمیگرداند.
  - **کد** همه را دوباره میسنجد: طول، لینک، @، هشتگ، تلفن، نام منبع، فارسی بودن و واژه‌های ممنوع. هر شکی یعنی رد.
  - منبعی که بیشتر موردهایش رد شود، خودکار خاموش میشود.
  - اگر چیزی آماده نباشد، پست با بانک محتوا میرود. پستی جا نمیافتد.
- **پل Claude** (`deploy/claude-bridge`): یک سرویس کوچک روی خود سرور، با کاربر جدا `proxyhub-claude`. Claude Code و ورود اشتراک مالک فقط در خانه‌ی همین کاربر است، نه در پنل و نه در ریپو.
  - پل روی سوکت `/var/lib/proxy-hub/claude-bridge/bridge.sock` گوش میدهد. فقط worker آن را میبیند (گروه `proxyhub-claude-sock`، GID 10101).
  - `claude -p` را **بی هیچ ابزاری** اجرا میکند. متن خبر فقط از stdin میرود، نه در خط فرمان.
  - سقف روزانه دارد و در هر لحظه فقط یک بررسی میکند. از محتوا هیچ لاگی نمیگیرد.
- deployer از این پس نسخه‌ی نصب‌شده‌ی پل را با هر استقرار سالم تازه میکند (فقط اگر نصب شده باشد).
- مهاجرت `0028_content_qc`.

1. **نصب پل** (با root):
   - این سه فایل را **کامل بخوان**: `deploy/claude-bridge/install.sh`، `deploy/claude-bridge/bridge.py` و `deploy/claude-bridge/proxyhub-claude-bridge.service`.
   - سپس `sudo bash deploy/claude-bridge/install.sh` را بزن.
   - این‌ها را بسنج و گزارش کن:
     - `getent group proxyhub-claude-sock` باید GID 10101 بدهد؛
     - `id proxyhub-claude` (کاربر سیستمی، بی shell)؛
     - `sudo ls -ld /var/lib/proxyhub-claude /var/lib/proxy-hub/claude-bridge` باید `drwx------` و `drwxr-s--- proxyhub-claude proxyhub-claude-sock` بدهد؛
     - `systemctl is-active proxyhub-claude-bridge` باید `active` بدهد؛
     - `sudo ls -l /var/lib/proxy-hub/claude-bridge/` باید `srw-rw----` بدهد.
   - `BR '{"op":"health"}'` هنوز باید `"ok": true` بدهد، با `claude_version: null` (Claude Code هنوز نصب نیست).
2. **نصب Claude Code برای کاربر پل** (نه برای root):
   - `AS bash -c 'cd ~ && curl -fsSL https://claude.ai/install.sh -o install-claude.sh'`
   - فایل `/var/lib/proxyhub-claude/install-claude.sh` را بخوان، سپس `AS bash /var/lib/proxyhub-claude/install-claude.sh` را بزن و بعد آن فایل را پاک کن.
   - `AS $CC --version` باید `2.1.259` یا بالاتر باشد.
   - به Claude Code خود سرور (کاربر root یا هر کاربر دیگر) **دست نزن.**
3. **ورود با اشتراک مالک** (مالک ترمینال ندارد):
   - اگر `tmux` نیست: `sudo apt-get install -y tmux`.
   - `AS env SHELL=/bin/bash bash -c "tmux new-session -d -s cclogin '$CC auth login --claudeai'"`، چند ثانیه صبر، سپس `AS tmux capture-pane -p -t cclogin`. (shell کاربر پل `nologin` است و tmux فرمان را با `$SHELL` اجرا میکند؛ بی `SHELL=/bin/bash` جلسه بی هیچ خطایی میمیرد. P22 روی سرور همین را نشان داد.)
   - **فقط نشانی ورود** (`https://claude.ai/...` یا `https://claude.com/...`) را برای مالک بفرست و بنویس: «این را در گوشی باز کنید، با همان حساب اشتراک Claude وارد شوید، تأیید کنید و کدی را که نشان میدهد فقط همین‌جا برای من بفرستید.»
   - کد مالک را با `AS tmux send-keys -t cclogin '<کد>' Enter` بده. کد را **هیچ‌جا ننویس**: نه در فایل، نه در گزارش، نه در ریپو.
   - `AS tmux capture-pane -p -t cclogin` باید ورود موفق را نشان دهد. سپس `AS tmux kill-session -t cclogin`.
   - `AS $CC auth status` باید `"loggedIn": true` بدهد. فقط `loggedIn` و `authMethod` را گزارش کن، نه ایمیل.
   - `sudo ls -la /var/lib/proxyhub-claude/.claude/` را بسنج: فایل ورود فقط برای `proxyhub-claude` خواندنی باشد.
   - اگر نشانی ورود نیامد یا کد پذیرفته نشد، خروجی `capture-pane` را بی کد گزارش کن و بایست.
4. **یک بررسی واقعی از راه سوکت، بی ابزار:**
   - `sudo systemctl restart proxyhub-claude-bridge`. سپس `systemctl show -p ActiveEnterTimestamp proxyhub-claude-bridge` را پیش و پس بسنج.
   - `BR '{"op":"health"}'` باید این‌ها را بدهد: `logged_in: true`، `version_ok: true` و `calls_24h: 0`.
   - یک بررسی کوچک:

     `BR '{"op":"review","protocol":1,"model":"sonnet","system":"Answer with one JSON object only: {\"sum\": <number>}.","content":[{"type":"text","text":"2+3"}],"timeout_s":120}'`

     انتظار: `"ok": true`، و در `text` عبارت `{"sum": 5}` یا مشابه آن.
   - `sudo journalctl -u proxyhub-claude-bridge -n 20 --no-pager` فقط باید خط‌هایی مثل `review outcome=ok duration_ms=… calls_24h=1` داشته باشد. اگر متن درخواست یا پاسخ در لاگ بود، **بایست** و گزارش بده.
   - `AS find /var/lib/proxyhub-claude/.claude/projects -type f -mmin -10 2>/dev/null | wc -l` باید `0` بدهد (هیچ گفت‌وگویی روی دیسک ذخیره نمیشود).
   - بی ابزار بودن را خود پل میسنجد: اگر Claude Code ابزاری اعلام کند، پاسخ `tools_present` است. اگر این را دیدی، بایست و گزارش بده.
5. **دسترسی worker به پل:**
   - `sudo docker compose -p proxyhub exec -T worker python -c 'import asyncio; from pathlib import Path; from proxyhub.content.claude_backends import BridgeBackend; print(asyncio.run(BridgeBackend(Path("/run/claude-bridge/bridge.sock"), "sonnet", 60).health()))'`

     انتظار: `'ok': True` و `'logged_in': True`.
   - `sudo docker compose -p proxyhub exec -T worker sh -c 'ffmpeg -hide_banner -version | head -n 1; ffprobe -hide_banner -version | head -n 1'`

     انتظار: دو خط نسخه (ffmpeg دبیان). اگر نبود، **بایست** و گزارش بده: بی آن هیچ ویدیویی بررسی نمیشود.
   - اگر `bridge_denied` آمد: `ls -ln /var/lib/proxy-hub/claude-bridge` و خروجی `id` در worker را گزارش کن. worker را بی دلیل restart نکن.
   - چند دقیقه بعد: `Q "SELECT value->'health' FROM settings WHERE key='content.qc.state'"` باید `"ok": true` داشته باشد.
6. **اولین تصمیم خودکار:**
   - `Q "SELECT count(*) FROM content_sources WHERE enabled"`. اگر `0` بود، از مالک بپرس: «یک کانال عمومی تلگرام برای آزمون ناظر بگویید.» **منبع را خودت انتخاب نکن.** کانالی را که مالک گفت از صفحه‌ی «منبع‌های محتوا» یا با API پنل اضافه کن.
   - تا نزدیک‌ترین پست صبر کن (ناظر از ۴۵ دقیقه پیش از هر پست کار میکند). سپس این‌ها را گزارش کن:
     - `Q "SELECT id, status, decided_by, qc_decision, qc_backend, qc_category, qc_checks, qc_flags FROM content_candidates WHERE qc_at IS NOT NULL ORDER BY qc_at DESC LIMIT 5"`
     - `Q "SELECT backend, outcome, reached, duration_ms FROM content_qc_calls ORDER BY id DESC LIMIT 5"`
     - `Q "SELECT action, target FROM actions_log WHERE action LIKE 'content.%' ORDER BY id DESC LIMIT 10"`
   - انتظار: دست‌کم یک مورد با `decided_by = qc` و `qc_backend = bridge`. اگر تأیید شد، در پست بعدی **کانال آزمایشی** میرود (`Q "SELECT id, content_candidate_id, media_kind FROM posts ORDER BY id DESC LIMIT 2"`). اگر همه رد شدند، پست با بانک محتوا میرود. هر دو درست است.
   - از مالک بخواه صفحه‌ی «صف بازبینی» را باز کند: کارت «ناظر محتوا (Claude)» باید «پل سالم و وارد شده» نشان دهد، و روی هر مورد بررسی‌شده، تصمیم و دلیل‌های Claude دیده شود.
   - اگر پستی با محتوای Claude رفت، از مالک بپرس تیتر و متن را روی آیفون چطور میبیند.
7. **گزارش پایانی** در یک بلوک کوتاه برای Claude ریپو: نتیجه‌ی هر گام، نسخه‌ی Claude Code، `health` بی ایمیل، سه ردیف آخر `content_qc_calls`، و ۳۰ خط لاگ برای هر خطا (بی محتوا).
