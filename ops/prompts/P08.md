# پرامپت ۸: استقرار فقط از `main` محافظت‌شده (تصمیم D31)

> این پرامپت را فقط وقتی اجرا کن که مالک PR شاخه‌ی کار را در `main` ادغام (merge) کرده و محافظت `main` را در گیت‌هاب روشن کرده باشد. مالک این را میچسباند: «`git fetch origin main && git checkout main && git pull` بزن، بعد فایل `ops/prompts/P08.md` را بخوان و دقیق اجرا کن.»

قاعده‌های `ops/prompts/README.md` برقرار است: فارسی با مالک؛ هیچ رمز، توکن یا کلید خصوصی در گزارش نیاید؛ در ریپو commit یا push نکن؛ هر فایلی را که با root اجرا میشود، پیش از اجرا بخوان.

**چرا:** تا امروز سرور از شاخه‌ی کار Claude مستقر میشد. از این به بعد فقط از `main` مستقر میشود، و هر تغییر یک PR است که خود مالک ادغام میکند. این کار پیش از ورود اولین توکن واقعی (ربات تلگرام، Cloudflare، هتزنر) لازم است.

کارها:
1. **پیش‌شرط:**
   - `git branch --show-current` در checkout خودت باید `main` بدهد. `ls ops/prompts/P08.md` باید فایل را نشان دهد.
   - `sudo grep -E '^(DEPLOY_BRANCH|PANEL_DOMAIN|AGENT_DOMAIN)=' /etc/proxy-hub/deploy.env` را بخوان و در گزارش بیاور.
   - `sudo bash ops/scripts/deploy_status.sh`: شاخه‌ی فعلی و commit مستقرشده را یادداشت کن.
2. **تغییر شاخه:**
   - `sudo cp -p /etc/proxy-hub/deploy.env /etc/proxy-hub/deploy.env.before-main`
   - `sudo sed -i 's/^DEPLOY_BRANCH=.*/DEPLOY_BRANCH=main/' /etc/proxy-hub/deploy.env`
   - `sudo grep -c '^DEPLOY_BRANCH=main$' /etc/proxy-hub/deploy.env` باید `1` بدهد. `sudo stat -c '%a %U' /etc/proxy-hub/deploy.env` و `sudo stat -c '%a %U' /etc/proxy-hub/deploy.env.before-main` باید یکی باشند.
3. **استقرار از `main`:**
   - `sudo systemctl start proxyhub-deployer.service`. این فرمان تا پایان استقرار صبر میکند.
   - `sudo journalctl -u proxyhub-deployer.service -n 40 --no-pager` باید با `ok: ... is healthy` تمام شود.
   - `sudo bash ops/scripts/deploy_status.sh` باید `branch: main` و `RESULT: up to date` بدهد.
   - اگر استقرار شکست خورد: `sudo cp -p /etc/proxy-hub/deploy.env.before-main /etc/proxy-hub/deploy.env` و `sudo systemctl start proxyhub-deployer.service`. سپس گزارش بده و ادامه نده.
4. **سنجش:**
   - `curl -s http://127.0.0.1:8000/healthz` باید `"status":"ok"` بدهد.
   - `curl -s -o /dev/null -w '%{http_code}\n' https://panel.beyra-ai.com/login` باید `200` بدهد.
   - اگر پرامپت ۷ اجرا شده است، `curl -s -w ' %{http_code}\n' https://agent.beyra-ai.com/agent/v1/desired` باید `{"error":"client_certificate_required"} 401` بدهد.
   - `sudo docker compose -p proxyhub exec -T postgres psql -U proxyhub -d proxyhub -At -c "SELECT version_num FROM alembic_version"` باید `0009_merge` یا تازه‌تر بدهد.
   - `sudo bash /opt/proxy-hub/deploy/monitoring/verify_stack.sh proxyhub` باید `ALL PASS` بدهد.
5. **پاک‌سازی:** `sudo rm /etc/proxy-hub/deploy.env.before-main`. پس از آن، checkout خودت را روی `main` نگه دار. پرامپت‌های بعدی همیشه با `git pull` روی `main` خوانده میشوند.
6. **گزارش پایانی** فارسی در یک بلوک برای Claude ریپو: نتیجه‌ی هر گام، خروجی `deploy_status.sh` پیش و پس، و ۴۰ خط پایانی journal استقرار. برای هر خطا ۳۰ خط لاگ، فقط با `sudo bash /opt/proxy-hub/deploy/monitoring/safe_logs.sh <service> 30`.

**نکن:**
- هیچ توکنی از مالک نخواه. ورود توکن‌ها گام بعدی است، در داشبورد.
- کلید توقف، سقف بودجه و سقف node را عوض نکن.
- `git push` نکن. شاخه‌ای در گیت‌هاب نساز.
