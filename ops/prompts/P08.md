# پرامپت ۸: استقرار فقط از `main`، با قفل ادغام روی خود سرور (D31 و D36)

> مالک این را میچسباند: «`git fetch origin main && git checkout main && git pull` بزن، بعد فایل `ops/prompts/P08.md` را بخوان و دقیق اجرا کن.» Claude ریپو PR شماره‌ی ۱ را پیش‌تر در `main` ادغام کرده است.

قاعده‌های `ops/prompts/README.md` برقرار است: فارسی با مالک؛ هیچ رمز، توکن یا کلید خصوصی در گزارش نیاید؛ در ریپو commit یا push نکن؛ هر فایلی را که با root اجرا میشود، پیش از اجرا بخوان.

**چرا:** از این به بعد سرور فقط از `main` مستقر میشود. GitHub Pro نداریم، پس قفل `main` روی خود سرور است: deployer فقط commitی را اجرا میکند که **ادغام یک PR به دست خود گیت‌هاب** باشد و **امضای کلید web-flow گیت‌هاب** را داشته باشد (`deploy/verify_main.sh`). هر commit که مستقیم روی `main` فرستاده شود، رد میشود و هشدار `DeployRefused` میآید.

کارها:
1. **پیش‌شرط:**
   - `git branch --show-current` در checkout خودت باید `main` بدهد. `git log -1 --format='%h %s'` باید با `Merge pull request #1 from` شروع شود.
   - پیش از اجرا بخوان: `deploy/verify_main.sh` و `deploy/deployer.sh` (بخش «Protected main»).
   - `sudo bash ops/scripts/deploy_status.sh` باید `RESULT: up to date` بدهد. شاخه هنوز `ccr-4e0296ec-n0ez5a` است.
   - `sudo test -x /usr/local/sbin/proxyhub-verify-main && echo ok` باید `ok` بدهد. این نسخه‌ی مورد اعتماد اسکریپت قفل است، که deployer پس از آخرین استقرار سالم نصب کرده است. اگر نبود، ادامه نده و گزارش بده.
   - `command -v gpg`. اگر چیزی نیامد: `sudo apt-get install -y gnupg`.
2. **کلید امضای گیت‌هاب:**
   - `curl -fsS https://github.com/web-flow.gpg -o ~/web-flow.gpg`
   - `gpg --show-keys --with-colons ~/web-flow.gpg | awk -F: '$1=="fpr"{print $10}'` باید **دقیقاً** `968479A1AFF927E37D1A566BB5690EEEBB952194` را در فهرست داشته باشد. این همان کلیدی است که در اسکریپت ثبت شده است. اگر نبود، ادامه نده و خروجی را گزارش بده.
   - `sudo install -m 0644 -o root -g root ~/web-flow.gpg /etc/proxy-hub/github-web-flow.gpg`
   - این فایل کلید **عمومی** است و رمز نیست.
3. **آزمون خشک قفل** پیش از عوض کردن شاخه. اسکریپت فقط میخواند و چیزی را عوض نمیکند:
   - `D=$(sudo cat /var/lib/proxy-hub/deployed_commit)`
   - `bash deploy/verify_main.sh "$PWD" "$D" HEAD ~/web-flow.gpg`
   - باید `verify-main: ok <hash> Merge pull request #1 ...` و در پایان `verify-main: OK (1 merge commit(s) ...)` بدهد. اگر `REFUSED` آمد، ادامه نده و خروجی کامل را گزارش بده.
   - آزمون منفی: `bash deploy/verify_main.sh "$PWD" none HEAD^2 ~/web-flow.gpg` باید `REFUSED` بدهد، چون آخرین commit شاخه‌ی کار ادغام PR نیست.
4. **تغییر شاخه:**
   - `sudo cp -p /etc/proxy-hub/deploy.env /etc/proxy-hub/deploy.env.before-main`
   - `sudo sed -i 's/^DEPLOY_BRANCH=.*/DEPLOY_BRANCH=main/' /etc/proxy-hub/deploy.env`
   - `sudo grep -c '^DEPLOY_BRANCH=main$' /etc/proxy-hub/deploy.env` باید `1` بدهد.
   - `sudo stat -c '%a %U' /etc/proxy-hub/deploy.env /etc/proxy-hub/deploy.env.before-main` باید برای هر دو یکی باشد.
5. **استقرار از `main`:**
   - `sudo systemctl start proxyhub-deployer.service`. این فرمان تا پایان استقرار صبر میکند.
   - `sudo journalctl -u proxyhub-deployer.service -n 40 --no-pager` باید این دو را نشان دهد: خط‌های `verify-main: ok ...` و `verify-main: OK`، و در پایان `ok: ... is healthy`.
   - `sudo bash ops/scripts/deploy_status.sh` باید `branch: main` و `RESULT: up to date` بدهد.
   - `cat /var/lib/proxy-hub/metrics/proxyhub_deploy.prom` باید `proxyhub_deploy_refused 0` داشته باشد.
   - اگر استقرار شکست خورد یا `REFUSED` آمد: `sudo cp -p /etc/proxy-hub/deploy.env.before-main /etc/proxy-hub/deploy.env` و `sudo systemctl start proxyhub-deployer.service`. سپس گزارش بده و ادامه نده.
6. **سنجش:**
   - `curl -s http://127.0.0.1:8000/healthz` باید `"status":"ok"` بدهد.
   - `curl -s -o /dev/null -w '%{http_code}\n' https://panel.beyra-ai.com/login` باید `200` بدهد.
   - `curl -s -w ' %{http_code}\n' https://agent.beyra-ai.com/agent/v1/desired` باید `{"error":"client_certificate_required"} 401` بدهد.
   - `SELECT version_num FROM alembic_version` (مثل P07) باید `0010_domains` یا تازه‌تر بدهد.
   - `sudo bash /opt/proxy-hub/deploy/monitoring/verify_stack.sh proxyhub` باید `ALL PASS` بدهد.
   - در Prometheus، قانون هشدار تازه بارگذاری شده باشد: `sudo docker compose -p proxyhub exec -T prometheus wget -qO- 'http://localhost:9090/api/v1/rules' | grep -c DeployRefused` باید دست‌کم `1` بدهد.
7. **پاک‌سازی:** `sudo rm /etc/proxy-hub/deploy.env.before-main` و `rm ~/web-flow.gpg`. checkout خودت را روی `main` نگه دار. پرامپت‌های بعدی همیشه با `git pull` روی `main` خوانده میشوند.
8. **گزارش پایانی** فارسی در یک بلوک برای Claude ریپو: نتیجه‌ی هر گام، خروجی کامل گام‌های ۲ و ۳، `deploy_status.sh` پیش و پس، و ۴۰ خط پایانی journal استقرار. برای هر خطا ۳۰ خط لاگ، فقط با `sudo bash /opt/proxy-hub/deploy/monitoring/safe_logs.sh <service> 30`.

**نکن:**
- هیچ توکنی از مالک نخواه. ورود توکن‌ها گام بعدی است، در داشبورد.
- کلید توقف، سقف بودجه و سقف node را عوض نکن.
- `git push` نکن. هیچ شاخه یا ریپویی در گیت‌هاب نساز یا پاک نکن.
