# پرامپت ۵: پایش، هشدار و backup (گام M1.7)

> مالک فقط این را میچسباند: «`git pull` بزن، بعد فایل `ops/prompts/P05.md` را بخوان و دقیق اجرا کن.»

قاعده‌های `ops/prompts/README.md` برقرار است: فارسی با مالک؛ هیچ رمز، توکن یا کلید خصوصی در خروجی نیاید؛ در ریپو commit یا push نکن؛ هر فایلی را که با root اجرا میشود، پیش از اجرا بخوان؛ پس از هر restart، `State.StartedAt` را پیش و پس بسنج.

**چه آمده است** (جزئیات: `deploy/monitoring/README.md`):
- شش سرویس تازه در همان stack `proxyhub`: `prometheus`، `alertmanager`، `loki`، `alloy` (فرستنده‌ی لاگ پنل)، `grafana` و `node-exporter`. همه با digest قفل شده‌اند. **هیچ‌کدام عمومی نیست.** فقط Grafana روی `127.0.0.1:3000` است.
- backup روزانه‌ی رمزنگاری‌شده با `age` در `/var/lib/proxy-hub/backups/` (۱۴ نسخه)، و آزمون بازگردانی هفتگی در یک Postgres موقت. هر دو با systemd timer اجرا میشوند.
- هشدارها: API از دسترس خارج، ضربان worker بیش از ۹۰ ثانیه کهنه، دیسک بیش از ۸۵٪، backup کهنه‌تر از ۲۶ ساعت، شکست آزمون بازگردانی.
- **گیرنده‌ی تلگرام هنوز خاموش است** (گیرنده‌ی null)، چون توکن ربات هشدار هنوز وارد نشده است. این درست است. در این پرامپت **هیچ توکنی نخواه و نگذار.**

کارها:
1. **دریافت و خواندن.** `git pull`. این فایل‌ها را پیش از اجرا با root بخوان: `deploy/install.sh`، `deploy/ensure_secrets.sh`، `deploy/docker-compose.yml`، همه‌ی فایل‌های `deploy/backup/`، `deploy/monitoring/check_configs.sh`، `deploy/monitoring/verify_stack.sh`، `deploy/monitoring/alertmanager/entrypoint.sh`، و چهار فایل `deploy/systemd/proxyhub-backup.*` و `deploy/systemd/proxyhub-restore-test.*`.
2. **جای دیسک، پیش از هر کار:** `df -h /` و `sudo docker system df`. imageهای تازه حدود ۴ گیگ جا میخواهند (Grafana به‌تنهایی ۲ گیگ)، و داده‌ی Prometheus تا ۵ گیگ میرسد. اگر جای خالی کمتر از ۱۲ گیگ است، **ادامه نده** و گزارش بده.
3. **استقرار خودکار را ببین.** deployer هر ۲ دقیقه commit تازه را مستقر میکند:
   - `sudo grep '^DEPLOY_BRANCH=' /etc/proxy-hub/deploy.env`. از این به بعد `BRANCH` همین نام است.
   - صبر کن تا `cat /var/lib/proxy-hub/deployed_commit` با `git rev-parse origin/BRANCH` یکی شود (حداکثر ۱۵ دقیقه؛ دریافت imageها طول میکشد). لاگ: `sudo journalctl -u proxyhub-deployer.service -n 60 --no-pager`.
   - اگر Docker Hub خطای `429` (سقف دریافت) داد، image را از جای دیگری نگیر. deployer همان commit را دوباره امتحان **نمیکند**، چون اگر `/healthz` سبز باشد آن را مستقرشده میداند، حتی وقتی سرویس‌های پایش بالا نیامده‌اند. پس یک ساعت صبر کن و `sudo FORCE=1 /usr/local/sbin/proxyhub-deploy` را بزن.
   - `sudo docker compose -p proxyhub ps`: هر شش سرویس تازه `Up` باشند؛ `prometheus`، `alertmanager`، `grafana` و `node-exporter` باید `healthy` باشند.
   - تا این لحظه پیام «age is not installed: backup_age_key not generated yet» در لاگ deployer طبیعی است. گام ۴ آن را درست میکند.
4. **نصب age و timerها، با اجرای دوباره‌ی نصب** (idempotent است و شاخه را عوض نمیکند): `sudo bash /opt/proxy-hub/deploy/install.sh BRANCH`. باید با exit 0 و «is healthy» تمام شود. سپس بسنج:
   - `age --version`
   - `sudo ls -l /etc/proxy-hub/secrets/`: **فقط نام و مجوز فایل‌ها، هرگز محتوا.** `backup_age_key` باید `-r--------` باشد. `grafana_admin_password` و سه فایل اختیاری `alert_bot_token`، `alert_chat_id` و `healthchecks_watchdog_url` باید `-r--r--r--` باشند. سه فایل اختیاری باید **خالی** باشند (اندازه‌ی `0`).
   - `sudo ls -l /etc/proxy-hub/backup_age_recipient` (کلید عمومی است و رمز نیست، ولی لازم نیست چاپش کنی).
   - `systemctl list-timers 'proxyhub-*' --no-pager`: سه timer دیده شود (`deployer`، `backup` و `restore-test`).
   - `ls -ld /var/lib/proxy-hub/backups /var/lib/proxy-hub/metrics`: اولی `drwx------` و دومی `drwxr-xr-x`.
5. **سنجش تنظیم‌ها با همان imageهای قفل‌شده** (کانتینرهای موقت بی شبکه): `sudo bash /opt/proxy-hub/deploy/monitoring/check_configs.sh`. باید `ALL PASS` بدهد: ۳ سنجش Prometheus (شامل آزمون واحد قانون‌ها)، ۵ حالت Alertmanager، Loki و Alloy.
6. **سنجش پشته‌ی در حال اجرا:**
   - یک خط لاگ تازه بساز: `curl -s -o /dev/null http://127.0.0.1:8000/p05-log-check`
   - `sudo bash /opt/proxy-hub/deploy/monitoring/verify_stack.sh proxyhub`. باید `ALL PASS` بدهد. در خروجی، خط `INFO alertmanager telegram receiver: off; external watchdog: off` طبیعی است.
   - **هیچ‌چیز عمومی نیست:** `sudo ss -ltnp | grep -E ':(3000|9090|9093|3100|9100|12345)\b'` فقط `127.0.0.1:3000` را نشان دهد.
   - `curl -s -o /dev/null -w "%{http_code}\n" https://panel.beyra-ai.com/internal/metrics` باید `404` بدهد.
   - `curl -s http://127.0.0.1:3000/api/health` باید `"database": "ok"` داشته باشد. رمز Grafana را نخوان و نشان نده.
7. **backup واقعی:**
   - `sudo systemctl start proxyhub-backup.service`، سپس `sudo journalctl -u proxyhub-backup.service -n 20 --no-pager`. باید خط `proxyhub-backup: ok: proxyhub-<زمان>.dump.age (... tables, ... rows ...)` بیاید.
   - `sudo ls -l /var/lib/proxy-hub/backups/`: یک `.dump.age` و یک `.manifest.age`، هر دو `-rw-------`.
   - رمزنگاری واقعی است: `sudo sh -c 'for f in /var/lib/proxy-hub/backups/proxyhub-*.age; do head -c 21 "$f"; echo; done'` برای هر فایل باید `age-encryption.org/v1` بدهد. هیچ dump رمزنشده‌ای نباید روی دیسک باشد: `sudo find / -xdev \( -name 'db.dump' -o -name 'proxyhub-*.dump' \) 2>/dev/null` خالی باشد.
   - `cat /var/lib/proxy-hub/metrics/proxyhub_backup.prom`: `proxyhub_backup_last_run_success 1`.
8. **آزمون بازگردانی واقعی:**
   - `sudo systemctl start proxyhub-restore-test.service`، سپس `sudo journalctl -u proxyhub-restore-test.service -n 20 --no-pager`. باید `PASS: ... restored; N tables and M rows match the manifest` بیاید.
   - `cat /var/lib/proxy-hub/restore_test.status`: `result=ok`.
   - کانتینر موقت پاک شده است: `sudo docker ps -a --filter label=proxyhub.purpose=restore-test` خالی باشد.
9. **سنجش هشدارها (واقعی، با Prometheus و Alertmanager خود سرور).** برای خواندن هشدارها این دو فرمان را به کار ببر:
   - Prometheus: `sudo docker compose -p proxyhub exec -T prometheus wget -q -O - http://127.0.0.1:9090/api/v1/alerts`
   - Alertmanager: `sudo docker compose -p proxyhub exec -T prometheus wget -q -O - http://alertmanager:9093/api/v2/alerts`

   در این گام **هیچ commit و push تازه‌ای نباید برسد**، چون deployer هنگام توقف worker، `/healthz` را ناسالم میبیند و برمیگردد.
   1. **متریک‌های backup به Prometheus رسیده‌اند:** `sudo docker compose -p proxyhub exec -T prometheus wget -q -O - 'http://127.0.0.1:9090/api/v1/query?query=proxyhub_backup_last_run_success'` مقدار `1` بدهد. همین را برای `proxyhub_restore_test_last_run_success` هم بسنج.
   2. **توقف عمدی worker (معیار «تمام شد» M1.7):** `State.StartedAt` کانتینر worker را بخوان. `sudo docker compose -p proxyhub stop worker`. **۳ دقیقه** صبر کن. هشدار `WorkerHeartbeatStale` باید در Prometheus `firing` باشد و در Alertmanager هم دیده شود، با متن فارسی «worker پنل از کار افتاده است». سپس `sudo docker compose -p proxyhub start worker`. `StartedAt` تازه باید عوض شده باشد. حداکثر تا ۲ دقیقه هشدار باید از هر دو جا برود و `/healthz` دوباره `"status":"ok"` بدهد.
   3. **شکست عمدی آزمون بازگردانی:** یک کلید نادرست موقت بساز: `d=$(sudo mktemp -d) && sudo age-keygen -o "$d/wrong.key" 2>/dev/null`. سپس `sudo PROXYHUB_BACKUP_KEY="$d/wrong.key" bash /opt/proxy-hub/deploy/backup/restore_test.sh`. باید `FAIL ... cannot decrypt the manifest` بدهد. حداکثر تا ۲ دقیقه `RestoreTestFailing` در Prometheus `firing` و در Alertmanager دیده شود. سپس `sudo rm -rf "$d"` و `sudo systemctl start proxyhub-restore-test.service` (با کلید درست). باید PASS شود و هشدار حداکثر تا ۲ دقیقه برود.
   4. **فرستادن به تلگرام:** چون گیرنده null است، پیامی به مالک نمیرسد. این **باز** میماند تا راه ورود توکن ربات هشدار با مالک روشن شود. توکن را از مالک در چت **نخواه**.
10. **پایداری پس از restart:**
    - `State.StartedAt` شش سرویس را بخوان: `for s in prometheus alertmanager loki alloy grafana node-exporter; do echo "$s $(sudo docker inspect -f '{{.State.StartedAt}}' "$(sudo docker compose -p proxyhub ps -q $s)")"; done`
    - `sudo docker compose -p proxyhub restart prometheus alertmanager loki alloy grafana node-exporter`
    - همان فرمان StartedAt را دوباره بزن: هر شش مقدار باید عوض شده باشند.
    - `sudo bash /opt/proxy-hub/deploy/monitoring/verify_stack.sh proxyhub` باید دوباره `ALL PASS` بدهد. Loki پس از restart حدود ۲۰ ثانیه طول میکشد تا آماده شود و اسکریپت صبر میکند.
    - داده مانده است: پرس‌وجوی `proxyhub_backup_last_run_success` گام ۹.۱ هنوز `1` بدهد. خروجی `verify_stack.sh` هم هنوز لاگ‌های پیش از restart را نشان دهد.
11. **پایان:** `df -h /` و `sudo docker system df`. `curl -s http://127.0.0.1:8000/healthz` باید `"status":"ok"` بدهد.
12. **گزارش پایانی** فارسی در یک بلوک برای Claude ریپو. نتیجه‌ی هر گام، خروجی کامل `check_configs.sh` و هر دو اجرای `verify_stack.sh`، خط‌های journal مربوط به backup و آزمون بازگردانی، زمان firing و رفتن هر هشدار در گام ۹، StartedAt پیش و پس، و جای دیسک پیش و پس. برای هر خطا ۳۰ خط لاگ (بی رمز) بیاور. لاگ کانتینرها را با `sudo docker compose -p proxyhub logs --no-color --tail 30 <service>` بگیر.

**نکن:**
- فایل‌های `alert_bot_token`، `alert_chat_id`، `healthchecks_watchdog_url` و `healthchecks_url` را پر نکن. توکن یا نشانی را از مالک در چت نخواه.
- محتوای هیچ فایلی در `/etc/proxy-hub/secrets/` را نخوان و چاپ نکن، از جمله `grafana_admin_password` و `backup_age_key`.
- پورتی در ufw باز نکن و Grafana یا Prometheus را عمومی نکن.
- `sudo docker compose -p proxyhub down -v` نزن، چون دیتابیس پنل پاک میشود. backupها را دستی پاک نکن.
- `ops/scripts/stack_restart_test.sh` را روی این سرور اجرا نکن (پرامپت ۲-ب).
