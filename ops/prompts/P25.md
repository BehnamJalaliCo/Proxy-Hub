# پرامپت ۲۵: رونمایی، بررسی ناوگان واقعی و کانال اصلی

> مالک این را میچسباند: «`git pull` بزن (روی `main`)، بعد فایل `ops/prompts/P25.md` را بخوان و تا رسیدن به نتیجه، خودت اجرا کن.»

قاعده‌های `ops/prompts/README.md` برقرار است:
- فارسی و **کوتاه** با مالک.
- هیچ رمز، کلید، IP کامل، لینک کامل پروکسی یا tag در گزارش نیاید.
- commit یا push نکن.

فرمان‌ها:
- `Q() { sudo docker compose -p proxyhub exec -T postgres psql -U proxyhub -d proxyhub -At -c "$1"; }`
- `W() { sudo docker compose -p proxyhub logs --since "$1" worker 2>&1 | grep -E "fleet|nodes|sponsor|publisher|Traceback" | tail -n 40; }`

**این پرامپت چیزی را عوض نمیکند.** مالک خودش در داشبورد این‌ها را میزند. تو فقط میسنجی و گزارش میدهی.

1. **قدم ۱ مالک: ناوگان** («تنظیمات ناوگان»: سقف بودجه ۱۰۰۰ یورو، سقف node ۱۰، حالت خشک خاموش):
   - `Q "SELECT value->>'kill_switch', value->>'dry_run', value->>'budget_cap_eur', value->>'node_cap_total', value->>'target_slots', value->>'creations_per_hour_cap', value->'locations' FROM settings WHERE key='fleet'"`.
   - انتظار: `false|false|1000|10|9|3|…`. اگر نبود، به مالک بگو کدام فیلد مانده و منتظر بمان.
   - مکان‌های بسته (مثل fsn1 روی همراه اول و رایتل) را خود planner کنار میگذارد (`proxyhub/fleet/locations.py`). فقط گزارش کن کدام مکان‌ها استفاده شدند.
2. **ساخت nodeها** (تا ۴ ساعت؛ هر ۳۰ دقیقه یک بار بسنج، نه بیشتر):
   - `Q "SELECT is_test, state, location, count(*) FROM nodes WHERE state NOT IN ('deleted') GROUP BY 1, 2, 3 ORDER BY 1, 2, 3"`.
   - `Q "SELECT action, allowed, count(*) FROM actions_log WHERE at > now() - interval '1 hour' AND (action LIKE 'fleet.%' OR action LIKE 'nodes.%') GROUP BY 1, 2 ORDER BY 3 DESC LIMIT 15"`.
   - انتظار: هر ساعت تا ۳ node تازه، تا ۹ node جایگاه‌دار. node آزمایشی هم میماند و جزو سقف ۱۰ است.
   - اگر خطای سقف هتزنر آمد (مثلاً `resource_limit_exceeded` یا `server_limit`)، بایست و به مالک بگو از کنسول هتزنر (Limits) افزایش سقف بخواهد.
   - هزینه‌ی ماه: `Q "SELECT round(sum(euros), 2) FROM cost_ledger WHERE day >= date_trunc('month', now())::date"`، و پیش‌بینی ماه از صفحه‌ی Overview داشبورد.
3. **اسپانسر هر node:**
   - `Q "SELECT r.state, count(*) FROM mtproxy_registrations r GROUP BY 1"`.
   - `Q "SELECT stuck_reason, count(*) FROM sponsor_flows WHERE created_at > now() - interval '6 hours' GROUP BY 1"`.
   - انتظار: برای هر node تازه یک ثبت `registered` با اسپانسر ‎@ipoxxo‎. ممکن است تا یک ساعت پس از ساخت طول بکشد.
4. **سنجش از ایران:** پس از READY، سنجش TLS هر node تازه از همراه اول، رایتل و … . فقط شمار باز و بسته را برای هر مکان گزارش کن، از صفحه‌ی Nodes یا جدول `probe_node_state`.
5. **قدم ۲ مالک: کانال اصلی.** فقط وقتی دست‌کم ۶ node جایگاه‌دار `ready` و ثبت‌شده باشند، به مالک بگو: «حالا در صفحه‌ی محتوا، انتشار در کانال اصلی را روشن کنید.» پیش از آن نه، چون کانال اصلی لینک node آزمایشی را نمیگیرد و پستی نمیرود.
   - پس از روشن شدن: `Q "SELECT value->>'main_enabled' FROM settings WHERE key='posting'"` باید `true` بدهد.
   - اولین پست کانال اصلی: `Q "SELECT id, role, created_at, breaking, media_kind FROM posts WHERE role = 'main' ORDER BY id DESC LIMIT 3"`.
   - `Q "SELECT count(*) FILTER (WHERE kind='mtproto'), count(*) FILTER (WHERE kind='reality') FROM post_links WHERE post_id = (SELECT max(id) FROM posts WHERE role='main')"`. انتظار: ۶ و ۱.
   - از مالک بخواه پست را در ‎@ipoxxo‎ ببیند و با یک حساب غیرعضو، یک لینک را امتحان کند. ‎@ipoxxo‎ باید بالای چت‌ها بیاید.
6. **گزارش پایانی** در یک بلوک کوتاه برای Claude ریپو: شمار nodeها به تفکیک مکان و حالت، ثبت‌ها، سنجش‌ها، اولین پست اصلی، هزینه‌ی ماه، و هر خطا با ۳۰ خط `W 1h`.

**نکن:**
- تنظیمات را خودت عوض نکن. سقف‌ها، حالت خشک و کانال اصلی با مالک است.
- node نساز و حذف نکن.
- `removal on` را نزن.
- `git push` نکن.
