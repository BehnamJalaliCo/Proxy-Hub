# پرامپت ۶: داشبورد روی دامنه، و ساخت ورود مالک (گام M1.3)

> مالک فقط این را میچسباند: «`git pull` بزن، بعد فایل `ops/prompts/P06.md` را بخوان و دقیق اجرا کن.» این پرامپت را پس از تمام شدن پرامپت ۵ اجرا کن.

قاعده‌های `ops/prompts/README.md` برقرار است: فارسی با مالک؛ هیچ رمز، توکن یا کلید خصوصی در گزارش نیاید؛ در ریپو commit یا push نکن؛ هر فایلی را که با root اجرا میشود، پیش از اجرا بخوان.

**چه آمده است:**
- داشبورد فارسی و راست‌به‌چپ پنل، از همان کانتینر `api` و پشت Caddy، روی `https://panel.beyra-ai.com`.
- ورود مالک با نام کاربری، رمز و کد ۶ رقمی برنامه‌ی Authenticator، به‌علاوه‌ی ۱۰ کد بازیابی یک‌بارمصرف.
- حساب مالک فقط با یک **لینک راه‌اندازی یک‌بارمصرف** ساخته میشود. این لینک ۶۰ دقیقه اعتبار دارد و توکنش بعد از `#` است، پس هرگز به سرور یا لاگ نمیرسد. در دیتابیس فقط hash آن ذخیره میشود. پس از ساخته شدن مالک، دیگر هیچ لینکی ساخته نمیشود.
- `/agent/*` روی دامنه‌ی پنل بسته است (۴۰۴). سایت جدای nodeها با mTLS در گام M2.1 میآید.
- کلید توقف روشن است و حالت خشک (dry-run) قفل است. **هیچ سروری ساخته نمیشود.**

کارها:
1. **پیش‌شرط:**
   - `sudo grep '^DEPLOY_BRANCH=' /etc/proxy-hub/deploy.env`. از این به بعد `BRANCH` همین نام است.
   - `cd /opt/proxy-hub && sudo git fetch -q origin BRANCH`. سپس `cat /var/lib/proxy-hub/deployed_commit` باید با `sudo git -C /opt/proxy-hub rev-parse origin/BRANCH` یکی باشد. اگر یکی نیست، تا ۱۰ دقیقه صبر کن (`sudo journalctl -u proxyhub-deployer.service -n 40 --no-pager`). اگر `/var/lib/proxy-hub/failed_commit` همان commit است، ادامه نده و گزارش بده.
   - `curl -s http://127.0.0.1:8000/healthz` باید `"status":"ok"` بدهد.
   - `docker compose version` باید v2.17 یا بالاتر باشد (ساخت داشبورد به آن نیاز دارد).
2. **سنجش دامنه از بیرون** (همه با `curl` روی همین سرور):
   - `curl -sI https://panel.beyra-ai.com/login`: کد `200`، `content-type: text/html` و سرآیند `content-security-policy` با `frame-ancestors 'none'` و `worker-src 'none'`. سرآیندهای `alt-svc`، `via` و `server` **نباید** باشند. این تغییرِ پس از گزارش پرامپت ۴ است.
   - هر کدام از این‌ها باید `404` بدهد: `/healthz`، `/livez`، `/internal/metrics`، `/agent/v1/register`، `/openapi.json`. برای هر کدام: `curl -s -o /dev/null -w "%{http_code}\n" https://panel.beyra-ai.com<path>`.
   - `curl -s -o /dev/null -w "%{http_code}\n" https://panel.beyra-ai.com/api/auth/me` باید `401` بدهد.
   - `curl -s -o /dev/null -w "%{http_code}\n" -X POST https://panel.beyra-ai.com/api/auth/login -H 'Content-Type: application/json' -d '{}'` باید `403` بدهد (سرآیند ضد CSRF نیست).
   - لاگ دسترسی خاموش است: `sudo docker compose -p proxyhub logs --since 5m api | grep -c 'GET /login'` باید `0` بدهد.
3. **ساخت لینک راه‌اندازی:**
   - `sudo docker compose -p proxyhub exec -T api python -m proxyhub setup-link --base-url https://panel.beyra-ai.com`
   - خروجی یک نشانی است به شکل `https://panel.beyra-ai.com/setup#...`. **فقط همین یک بار، در همین چت، به مالک نشانش بده.** آن را در هیچ فایلی ننویس و در گزارش پایانی نگذار.
   - اگر خطای `an admin account already exists` آمد، یعنی حساب مالک پیش‌تر ساخته شده است. ادامه نده و گزارش بده.
4. **راهنمای مالک.** این متن را برای مالک بفرست و صبر کن تا بگوید تمام شد:
   - «لینک را روی **گوشی** باز کنید. ۶۰ دقیقه اعتبار دارد و فقط یک بار کار میکند.
   - مرحله‌ی ۲: یک برنامه‌ی Authenticator لازم است (Google Authenticator، Microsoft Authenticator یا 2FAS). دکمه‌ی «افزودن به Authenticator همین گوشی» را بزنید. اگر کار نکرد، «کپی کلید» را بزنید و در برنامه با گزینه‌ی «Enter a setup key» وارد کنید. نام حساب در برنامه «IPOXXO Panel» است.
   - مرحله‌ی ۳: یک نام کاربری (۳ تا ۳۲ نویسه‌ی انگلیسی) و یک رمز دست‌کم ۱۲ نویسه‌ای بسازید. کد ۶ رقمی برنامه را هم وارد کنید. رمز را در یک جای امن نگه دارید، مثلاً مدیر رمز گوشی.
   - مرحله‌ی ۴: ۱۰ کد بازیابی نشان داده میشود، **فقط همین یک بار**. اگر گوشی یا برنامه‌ی Authenticator از دست برود، فقط با این کدها میشود وارد شد. آن‌ها را جایی بیرون از این گوشی نگه دارید (روی کاغذ، یا در مدیر رمز). در هیچ چتی نفرستید، حتی برای من.
   - بعد یک بار خارج شوید (منوی پایین، کنار نام کاربری) و دوباره با نام کاربری، رمز و کد ۶ رقمی وارد شوید.
   - **رمز، کد ۶ رقمی، کدهای بازیابی و اسکرین‌شات صفحه‌ی QR را برای هیچ‌کس، از جمله من، نفرستید.**»
5. **سنجش پس از کار مالک.** فقط شمارش از جدول رویدادها، هیچ مقدار رمزی:
   - `sudo docker compose -p proxyhub exec -T postgres psql -U proxyhub -d proxyhub -c "SELECT action, count(*) FROM actions_log WHERE actor = 'auth' GROUP BY action ORDER BY action"`
   - باید `setup_link_created`، `setup_completed` و دست‌کم یک `login_ok` و یک `logout` دیده شود.
   - `sudo docker compose -p proxyhub exec -T postgres psql -U proxyhub -d proxyhub -c "SELECT count(*) AS admins FROM admin_users"` باید `1` بدهد.
   - لینک دوم ساخته نمیشود: فرمان گام ۳ را دوباره بزن. باید خطا بدهد. خروجی را در گزارش بیاور، چون در آن حالت توکنی در کار نیست.
   - هیچ IP ذخیره نشده است: `sudo docker compose -p proxyhub exec -T postgres psql -U proxyhub -d proxyhub -At -c "SELECT count(*) FROM information_schema.columns WHERE table_name LIKE 'admin_%' AND (column_name ILIKE '%ip%' OR data_type = 'inet')"` باید `0` بدهد.
6. **گزارش پایانی** فارسی در یک بلوک برای Claude ریپو: نتیجه‌ی هر گام، سرآیندهای گام ۲ (بی کوکی)، خروجی گام ۵، و هر چیزی که مالک درباره‌ی ظاهر و کار داشبورد گفت. برای هر خطا ۳۰ خط لاگ، فقط با `sudo bash /opt/proxy-hub/deploy/monitoring/safe_logs.sh <service> 30`.

**نکن:**
- لینک راه‌اندازی، توکن، رمز، کد ۶ رقمی یا کد بازیابی را در گزارش، فایل یا لاگ نگذار.
- تنظیمات ناوگان یا کلید توقف را از داشبورد عوض نکن و از مالک هم نخواه. ساخت سرور در این مرحله قفل است.
- توکن هتزنر یا هیچ توکن دیگری را از مالک نخواه. افزودن حساب هتزنر گام جدایی است.
