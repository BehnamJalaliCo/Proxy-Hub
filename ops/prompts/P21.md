# پرامپت ۲۱: شش پروکسی ترکیبی (D49) و برچسب اپراتور (D50)

> مالک این را میچسباند: «`git pull` بزن (روی `main`)، بعد فایل `ops/prompts/P21.md` را بخوان و تا رسیدن به نتیجه، خودت اجرا کن.»

قاعده‌های `ops/prompts/README.md` برقرار است:
- فارسی و **کوتاه** با مالک.
- هیچ رمز، کلید، لینک، uuid، secret یا tag کامل در گزارش نیاید.
- commit یا push نکن.

فرمان: `Q() { sudo docker compose -p proxyhub exec -T postgres psql -U proxyhub -d proxyhub -At -c "$1"; }`

**چه عوض شد (PR ۲۳):**
- **D49:**
  - هر پست ۶ لینک MTProto دارد: اول یکی از هر node. اگر node کمتر از ۶ باشد، با لینک‌های **اضافه‌ی** همان nodeها پر میشود.
  - هر لینک اضافه یک کاربر Telemt جدا با secret خودش است (`mt_<node>_x<n>`)، روی همان پورت و نام.
  - همان tag اسپانسر node را دارد و هرگز در ‎@MTProxybot‎ ثبت نمیشود.
  - تا node زنده است حذف نمیشود و با node از کار میافتد.
  - با یک node، آن node ۶ لینک دارد (اصلی + ۵ اضافه).
- **D50:**
  - لینکی که سنجش TLS خود پنل در ۶ ساعت گذشته آن را از شبکه‌ی یک اپراتور **باز** دیده باشد، میتواند نام آن اپراتور را بگیرد. هر اپراتور حداکثر ۲ لینک، به ترتیب همراه اول و رایتل. بقیه «پروکسی» میمانند. ایرانسل هرگز نام نمیگیرد (تصمیم مالک).
  - نامی که در پست تکرار شود شماره میگیرد. پیش از امضا یک خط «—» میآید.
  - نقطه‌ی همراه اول در Globalping گاهی خاموش است. در آن حالت، نام «همراه اول» نمیآید.
- مهاجرت‌ها: `0025_mtproto_extras` و `0026_post_link_operator`.

1. **پیش‌شرط:**
   - `deploy_status.sh` باید `RESULT: up to date` بدهد.
   - `Q "SELECT version_num FROM alembic_version"` باید `0026_post_link_operator` بدهد.
   - شمار خطای worker باید ۰ باشد.
   - `Q "SELECT value->>'max_mtproto' FROM settings WHERE key='posting'"` (اگر خالی بود، پیش‌فرض ۶ است).
2. **لینک‌های اضافه** (تا ۵ دقیقه):
   - `Q "SELECT ordinal, disabled_at IS NULL FROM mtproto_proxies ORDER BY node_id, ordinal"`. انتظار برای node آزمایشی: ordinal از ۰ تا ۵، همه فعال.
   - `Q "SELECT count(*), count(*) FILTER (WHERE name LIKE '%\_x%'), count(DISTINCT ad_tag) FROM telemt_users WHERE enabled"`. انتظار: ۶ کاربر، ۵ اضافه، و فقط **یک** tag یکتا. اگر اسپانسر هنوز تنظیم نشده بود، ۰ tag.
   - هیچ ثبت تازه‌ای برای اضافه‌ها نباید باشد: `Q "SELECT count(*) FROM sponsor_flows WHERE user_name LIKE '%\_x%'"` باید ۰ باشد.
   - عامل node باید حالت تازه را گرفته باشد: `applied_etag` گزارش عامل باید با حالت مطلوب برابر باشد (همان روش P10 و P16).
3. **پست** (کانال آزمایشی):
   - پست تازه‌ی بعدی باید ۶ لینک داشته باشد. اگر تا ۳۰ دقیقه پستی نرفت، یک `try_run_once` بزن، با patch فقط برای slot همان اجرا (روش P19).
   - گزارش کن: `Q "SELECT position, operator FROM post_links WHERE post_id = (SELECT max(id) FROM posts) AND kind = 'mtproto' ORDER BY position"`.
   - گزارش کن کدام نام‌ها آمدند (همراه اول، رایتل یا پروکسی) و آخرین سنجش هر شبکه چه بود.
   - از مالک بخواه روی آیفون **چند لینک را جدا امتحان کند**، دست‌کم یک لینک اصلی و دو لینک اضافه. هر کدام باید وصل شود و ‎@ipoxxo‎ را اسپانسر نشان دهد. خط «—» هم باید پیش از «🔗 @ipoxxo» باشد.
4. **داشبورد:** صفحه‌ی MTProto باید لینک‌های اضافه را با نام «پروکسی ۱، لینک ۲» و مانند آن نشان دهد. از مالک بخواه نگاه کند.
5. **گزارش پایانی** در یک بلوک کوتاه برای Claude ریپو.
