# پرامپت ۲۶: حذف خودکار پروکسی‌های مرده از ‎@MTProxybot‎ (removal on)

> مالک این را میچسباند: «`git pull` بزن (روی `main`)، بعد فایل `ops/prompts/P26.md` را بخوان و تا رسیدن به نتیجه، خودت اجرا کن.»

قاعده‌های `ops/prompts/README.md` برقرار است:
- فارسی و **کوتاه** با مالک.
- هیچ رمز، tag، secret یا نشانی کامل در گزارش نیاید. نشانی را فقط با ۲ بخش آخرش بنویس (مثل `…209.24`) یا با نام slot.
- commit یا push نکن.

فرمان‌ها:
- `Q() { sudo docker compose -p proxyhub exec -T postgres psql -U proxyhub -d proxyhub -At -c "$1"; }`
- `C2="sudo docker compose -p proxyhub exec -T api python -m proxyhub.sponsor"`

**چرا:** پس از رونمایی، nodeهای بسته‌شده خودکار میسوزند و حذف میشوند (P25: s1 در fsn1 و s2 در nbg1). ثبتشان در فهرست ‎@MTProxybot‎ حساب دوم میماند و با چرخش nodeها فهرست شلوغ میشود.
- پنل فقط پروکسی‌ای را پاک میکند که **سرورش حذف شده** و خود ما ثبتش کرده‌ایم (docs/11، بخش ۲.۲). پروکسی فعال، بازنشسته یا ناشناس هرگز پاک نمیشود.
- «حذف» فقط وقتی روشن میشود که یک دور **مشاهده** دقیقاً یک دکمه‌ی حذف با شکل شناخته‌شده («Delete proxy») زیر صفحه‌ای با نشانی همان پروکسی دیده باشد.
- **صفحه‌ی تأیید حذف ربات هنوز هرگز دیده نشده است.** اگر شکلش با الگوی کد (`CONFIRM_BUTTON` در `proxyhub/mtproxy/userclient.py`) نخواند، جریان میایستد و شکل صفحه را ثبت میکند. در آن حالت چیزی پاک نشده است. فقط گزارش کن تا Claude ریپو الگو را درست کند.

0. **پیش‌شرط:**
   - `deploy_status.sh` باید `RESULT: up to date` بدهد. شمار خطای worker باید ۰ باشد.
   - کلید توقف خاموش و حساب دوم وصل: `Q "SELECT value->>'kill_switch' FROM settings WHERE key='fleet'"` باید `false` و `Q "SELECT value->>'state' FROM settings WHERE key='mtproxy.account'"` باید `connected` بدهد.
1. **آیا پروکسی مرده‌ای هست؟**
   - `Q "SELECT is_test, state, location, count(*) FROM nodes GROUP BY 1, 2, 3 ORDER BY 1, 2, 3"`.
   - `Q "SELECT state, state_reason, count(*) FROM mtproxy_registrations GROUP BY 1, 2 ORDER BY 1, 2"`. ثبت node حذف‌شده `retired|node_gone` میشود.
   - اگر s1 و s2 هنوز `burned` اند و `deleted` نشده‌اند، پنل اول جایگزین را میسازد و بعد سوخته را حذف میکند (D14). هر ۳۰ دقیقه بسنج، حداکثر ۴ ساعت. تا وقتی ثبتی با `node_gone` نیست، به گام ۲ نرو.
2. **خواندن فهرست:** `$C2 inventory`، بعد `$C2 wait --timeout 1800`، بعد `$C2 status`.
   - گزارش کن: `counts` (live، gone، retired، unknown، removable، promotion_ok، promotion_problem) و `removal_enabled`.
   - اگر `removable` صفر بود، بایست و گزارش بده.
3. **مشاهده** (حذف هنوز خاموش است): `$C2 cleanup`، بعد `$C2 wait --timeout 1800`، بعد `$C2 status`.
   - `observation.result` باید `remove_button_found` باشد: دقیقاً یک دکمه‌ی حذف، زیر پیامی با نشانی همان پروکسی.
   - شکل صفحه (`screens`) را گزارش کن، بی نشانی کامل و بی tag.
   - اگر موفق نبود، بایست و گزارش بده. حذف را روشن نکن.
4. **روشن کردن حذف:** `$C2 removal on`. خروجی باید `"removal_enabled": true` بدهد. اگر `mtproxybot_not_observed` داد، بایست.
5. **حذف واقعی:** `$C2 cleanup`، بعد `$C2 wait --timeout 3600`، بعد `$C2 status`.
   - گزارش کن: چند پروکسی پاک شد (`counts.gone` پیش و پس)، و اگر کار ایستاد، `job` (دلیل و گام) و **شکل صفحه‌ی تأیید** در `screens`، بی نشانی و بی tag.
   - `Q "SELECT action, count(*) FROM actions_log WHERE action LIKE 'sponsor.mtproxybot%' AND at > now() - interval '2 hours' GROUP BY 1"`.
6. **وارسی:**
   - `$C2 inventory`، `$C2 wait --timeout 1800`، `$C2 status`. انتظار: `removable` صفر یا کمتر از پیش، و همه‌ی پروکسی‌های فعال هنوز `live` با `promotion_ok`.
   - از مالک بخواه در حساب دوم، در ‎@MTProxybot‎ دستور ‎/myproxies‎ را بزند و ببیند پروکسی‌های مرده رفته‌اند و پروکسی‌های فعال مانده‌اند.
7. **حذف روشن میماند**، تا nodeهای سوخته‌ی بعدی خودکار پاک شوند. اگر جایی چیزی غیرمنتظره دیدی (پروکسی فعالی پاک شد، یا ربات صفحه‌ی ناشناس داد)، فوراً `$C2 removal off` بزن و گزارش بده.
8. **گزارش پایانی** در یک بلوک کوتاه برای Claude ریپو.

**نکن:**
- هیچ پروکسی را با دست در ‎@MTProxybot‎ پاک نکن.
- تنظیمات دیگر را عوض نکن. فقط `removal on`، و در صورت خطر `removal off`.
- node نساز و حذف نکن.
- `git push` نکن.
