# پرامپت ۱۶: دور ۵ روی سرور. XHTTP، سنجش TLS از ایران، مکان و سایت هدف خودکار

> مالک این را میچسباند: «`git pull` بزن (روی `main`)، بعد فایل `ops/prompts/P16.md` را بخوان و تا رسیدن به نتیجه، خودت اجرا کن.»

قاعده‌های `ops/prompts/README.md` برقرار است:
- فارسی و **کوتاه** با مالک.
- هیچ رمز، کلید، لینک یا uuid در گزارش نیاید.
- commit یا push نکن.

اجازه‌های P15 هم برقرار است: با CLI پنل **یک** node آزمایشی بساز یا بازنشسته کن، زیر همه‌ی قفل‌ها.

فرمان‌ها:
- `C="sudo docker compose -p proxyhub exec -T api python -m proxyhub.nodes"`
- `Q() { sudo docker compose -p proxyhub exec -T postgres psql -U proxyhub -d proxyhub -At -c "$1"; }`

1. **پیش‌شرط:**
   - `deploy_status.sh` باید `RESULT: up to date` بدهد.
   - `Q "SELECT version_num FROM alembic_version"` باید `0020_merge` بدهد.
   - شمار خطای worker باید ۰ باشد. در لاگ worker باید `probes: … measured by TLS from Iran` و `targets: …` دیده شود.
   - تنظیمات ناوگان: مکان‌ها باید **فقط `hel1`** باشد. اگر نیست، از مالک بخواه در «تنظیمات» بگذارد.
2. **node تازه با عامل 0.4.0:**
   - node آزمایشی فعلی را با `$C retire <ID>` بازنشسته کن و صبر کن تا حذف شود.
   - `$C test-node --location hel1` و بعد `$C wait <ID> ready --timeout 1500`.
   - `Q "SELECT agent_version FROM agent_nodes WHERE node_id='<ID>'"` باید `0.4.0` بدهد.
   - صفحه‌ی Reality باید روی حالت Reality با XHTTP روشن باشد.
   - تا چند دقیقه، `Q "SELECT xhttp_port, up, apply_error FROM reality_node_status WHERE node_id='<ID>'"` باید `2083|t|` بدهد.
3. **سنجش‌های خودکار** (۳۰ تا ۶۰ دقیقه صبر کن، بعد گزارش بده):
   - `Q "SELECT kind, status, count(*) FROM probe_measurements WHERE at > now()-interval '1 hour' GROUP BY 1,2"`. ردیف‌های `https` باید باشند.
   - `Q "SELECT n.location, s.verdict FROM probe_node_state s JOIN nodes n ON n.id=s.node_id"`. node در hel1 باید `ok` باشد.
   - `Q "SELECT location, network, state FROM probe_location_reach ORDER BY 1,2"`.
   - `Q "SELECT host, iran->'asn:197207'->>'state', iran->'asn:57218'->>'state' FROM target_states"`.
   - `Q "SELECT action, target, reasons->'context' FROM actions_log WHERE action IN ('target_auto_switched','target_no_candidate') ORDER BY id DESC LIMIT 10"`. هدف Reality و دامنه‌ی MTProto باید به سایتی رفته باشند که از ایران باز است (نه `www.microsoft.com`).
4. **یک آزمون از مالک** (گوشی، **VPN خاموش**). از او بخواه این را **یک بار با اینترنت گوشی** انجام دهد:
   - لینک «کانفیگ N (XHTTP)» را در V2BOX وارد کند و fast.com را باز کند. عدد؟
   - همین را با لینک «کانفیگ N (TCP)» تکرار کند. عدد؟
   - لینک MTProto را در تلگرام وصل کند (Use Proxy روشن) و یک ویدیو باز کند. دانلود شد؟
   - اپراتورش را بگوید.
5. **اگر MTProto کُند بود**، در همان زمان این را بگیر:
   `Q "SELECT at, load1, cpu_count, me_route_drops_total, accept_permit_timeouts_total, connections_total FROM agent_node_reports WHERE node_id='<ID>' ORDER BY at DESC LIMIT 30"`
   - اگر `load1` به‌طور پیوسته از `cpu_count` بیشتر بود، مشکل CPU است.
   - اگر `me_route_drops_total` بالا رفت، Telemt داده‌ی کلاینت کُند را دور میریزد.
   - اگر همه ثابت ماند، محدودیت بیرون از node است.
6. **داشبورد:** در صفحه‌های MTProto، Reality و nodeها، بخش «پایان‌یافته‌ها» جدا باشد. در صفحه‌ی nodeها جدول «locationها از ایران» باشد، و در تنظیمات کارت «سایت‌های هدف (SNI)».
7. **گزارش پایانی** در یک بلوک کوتاه برای Claude ریپو:
   - نتیجه‌ی هر گام؛
   - دو عدد سرعت (XHTTP و TCP) و نتیجه‌ی MTProto؛
   - اپراتور.
   - node آزمایشی را نگه دار.

**نکن:**
- تنظیمات را خودت عوض نکن.
- بیش از یک node نساز.
- `git push` نکن.
