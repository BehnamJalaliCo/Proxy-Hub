# پرامپت ۱۸: قالب تازه‌ی پست، دو دکمه‌ی پاک‌سازی، فهرست ‎@MTProxybot‎، بسته‌ی ایموجی

> مالک این را میچسباند: «`git pull` بزن (روی `main`)، بعد فایل `ops/prompts/P18.md` را بخوان و تا رسیدن به نتیجه، خودت اجرا کن.»

قاعده‌های `ops/prompts/README.md` برقرار است:
- فارسی و **کوتاه** با مالک.
- هیچ رمز، کلید، لینک یا uuid در گزارش نیاید.
- commit یا push نکن.

فرمان‌ها:
- `Q() { sudo docker compose -p proxyhub exec -T postgres psql -U proxyhub -d proxyhub -At -c "$1"; }`
- `C2="sudo docker compose -p proxyhub exec -T api python -m proxyhub.sponsor"`

**چه عوض شد:**
- **قالب پست:**
  - پروکسی‌ها «⚡ اتصال ۱» هستند، به شکل لینک.
  - هر کانفیگ در کادر کد است، با دکمه‌ی کپی و برچسب TCP یا XHTTP.
  - «کانفیگ شماره» دیگر نیست.
  - پست‌های ۴۸ ساعت اخیر یک بار به قالب تازه ویرایش میشوند.
- **دو دکمه (D44):**
  - «پاک کردن پایان‌یافته‌ها» در صفحه‌های MTProto، Reality، nodeها و تنظیمات.
  - «پاک کردن کانال آزمایشی» در صفحه‌ی تلگرام.
- **‎@MTProxybot‎:** فهرست خوانده و در صفحه‌ی اسپانسر نشان داده میشود. پاک کردن پروکسی‌های مرده فعلاً فقط در حالت «مشاهده» است.
- **بسته‌ی ایموجی:**
  - با یک ایموجی ساخته میشود و بقیه دقیقه‌ای ۳ تا اضافه میشوند.
  - پس از 429 همان زمانی صبر میکند که تلگرام میگوید.

1. **پیش‌شرط:**
   - `deploy_status.sh` باید `RESULT: up to date` بدهد.
   - `Q "SELECT version_num FROM alembic_version"` باید `0022_mtproxybot_inventory` بدهد.
   - شمار خطای worker باید ۰ باشد.
2. **بسته‌ی ایموجی** (تا ۲۰ دقیقه):
   - `Q "SELECT jsonb_array_length(value->'alts'), value->>'error', value->>'retry_at' FROM settings WHERE key='posts.own_pack'"`. شمار باید تا ۲۸ برسد.
   - `Q "SELECT action, target FROM actions_log WHERE action LIKE 'posts.own_pack%' ORDER BY id DESC LIMIT 5"` باید `posts.own_pack_created`، سپس `posts.own_pack_extended` و `posts.own_pack_chosen` نشان دهد.
   - از مالک بخواه: در صفحه‌ی «محتوا» لینک بسته را باز کند و بگوید ایموجی‌ها را میبیند. سپس «بررسی حالا» را بزند.
   - پست بعدی کانال آزمایشی باید ایموجی متحرک داشته باشد.
3. **قالب پست:** از مالک بپرس پست تازه‌ی کانال آزمایشی چطور است:
   - کادرهای کد با دکمه‌ی کپی؛
   - برچسب TCP و XHTTP؛
   - «⚡ اتصال».

   سپس `sudo docker compose -p proxyhub exec -T api python -m pytest -q tests/test_posts_real.py` را بزن (اگر متغیرهای آزمون واقعی ربات را ندارد و skip شد، بگو).
4. **پاک کردن کانال آزمایشی** (مالک):
   - مالک در تلگرام به ربات در **کانال آزمایشی** اجازه‌ی «حذف پیام‌ها» را بدهد، **فقط همان کانال**.
   - در صفحه‌ی تلگرام «پاک کردن کانال آزمایشی» را بزند و «پاک کن» را تایپ کند.
   - نتیجه: شمار پیام‌های پاک‌شده و آنچه ماند (پیام‌های بیش از ۴۸ ساعت را تلگرام اجازه‌ی حذف نمیدهد).
   - **سپس مالک اجازه‌ی حذف ربات را بردارد.**
5. **پاک کردن پایان‌یافته‌ها** (مالک، از صفحه‌ی nodeها یا تنظیمات):
   - دکمه را بزند. پیش‌نمایش شمار هر بخش و دلیل نگه‌داشتن‌ها را نشان میدهد.
   - تأیید کند. `Q "SELECT context FROM actions_log WHERE action='cleanup.ended_purged' ORDER BY id DESC LIMIT 1"` را گزارش کن.
6. **فهرست ‎@MTProxybot‎ (اجرای مشاهده):**
   - `$C2 status` باید `removal_enabled: false` و `cleanup_mode: observe` بدهد.
   - `$C2 inventory`، بعد `$C2 wait --timeout 3600`، بعد `$C2 status`. گزارش کن:
     - `list` (pages، complete، note، total) و `counts`؛
     - برای هر ردیف: address، status، listed، exact، promotion، sponsor_channel؛
     - همه‌ی `screens` (شکل دکمه‌ها؛ آدرس‌ها و hex خودبه‌خود پوشیده است)؛
     - آیا ردیفی `exact: true` دارد؟
   - سپس `$C2 cleanup`، `$C2 wait --timeout 3600` و `$C2 status`. `observation` و `proxy_screen` پروکسی مرده را گزارش کن: متن و برچسب همه‌ی دکمه‌ها.
   - **`removal on` را نزن.** پس از گزارش تو، پاک کردن واقعی را روشن میکنیم.
   - از مالک بخواه صفحه‌ی اسپانسر را ببیند. جدول ‎@MTProxybot‎ باید روشن نشان دهد کدام پروکسی فعال است و کدام مرده، و ‎@ipoxxo‎ روی پروکسی‌های فعال تنظیم است یا نه.
7. **گزارش پایانی** در یک بلوک کوتاه برای Claude ریپو.

**نکن:**
- تنظیمات را خودت عوض نکن.
- بیش از یک node نساز.
- `git push` نکن.
- `removal on` را نزن.
- به کانال اصلی دست نزن.
