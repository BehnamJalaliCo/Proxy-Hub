# پرامپت ۹: سنجش واقعی ربات تلگرام پنل

> مالک این را میچسباند: «`git pull` بزن (روی `main`)، بعد فایل `ops/prompts/P09.md` را بخوان و دقیق اجرا کن.» این پرامپت پس از آن است که مالک ربات را در داشبورد ثبت کرده، چت خودش را وصل کرده، کانال آزمایشی را ثبت کرده و «هشدار آزمایشی» و «پست آزمایشی» را زده است.

قاعده‌های `ops/prompts/README.md` برقرار است: فارسی با مالک؛ هیچ رمز، توکن یا کلید خصوصی در گزارش نیاید؛ در ریپو commit یا push نکن؛ هر فایلی را که با root اجرا میشود، پیش از اجرا بخوان.

**هدف:** ثابت کردن چهار چیز روی ربات واقعی:
1. ربات، چت مالک و کانال آزمایشی درست ثبت شده‌اند و ربات اجازه‌ی حذف ندارد.
2. **ویرایش** پست کار میکند. پست‌ها هرگز حذف نمیشوند، فقط ویرایش (قانون ۶).
3. مسیر هشدار واقعی کار میکند: Alertmanager ← webhook پنل ← ربات ← تلگرام مالک.
4. توکن ربات در هیچ لاگی نیست.

در این پرامپت هیچ چیزی به **کانال اصلی** فرستاده نمیشود. فقط کانال آزمایشی و چت خصوصی مالک.

فرمان پایه‌ی پایگاه‌داده در گام‌های زیر:
`Q() { sudo docker compose -p proxyhub exec -T postgres psql -U proxyhub -d proxyhub -At -c "$1"; }`

کارها:
1. **پیش‌شرط:**
   - `sudo bash ops/scripts/deploy_status.sh` باید `branch: main` و `RESULT: up to date` بدهد.
   - `curl -s http://127.0.0.1:8000/healthz` باید `"status":"ok"` بدهد.
2. **وضعیت ثبت‌شده** (بی توکن و بی شناسه‌ی چت):
   - `Q "SELECT action, allowed, count(*) FROM actions_log WHERE action LIKE 'telegram.%' GROUP BY 1,2 ORDER BY 1"`. باید دست‌کم این‌ها با `t` باشند: `telegram.bot_set`، `telegram.pairing_created`، `telegram.owner_paired`، `telegram.channel_set`، `telegram.test_alert`، `telegram.test_post`.
   - `Q "SELECT key FROM settings WHERE key LIKE 'telegram.%' ORDER BY key"`. باید `telegram.bot`، `telegram.channels` و `telegram.owner` در فهرست باشند.
   - `Q "SELECT value->'test'->>'can_post', value->'test'->>'can_edit', value->'test'->>'can_delete' FROM settings WHERE key='telegram.channels'"` باید `true|true|false` بدهد.
     - اگر `can_delete` برابر `true` بود، ادامه نده. به مالک بگو در تنظیمات ادمین کانال آزمایشی، اجازه‌ی «Delete messages» ربات را بردارد و دوباره کانال را در داشبورد ثبت کند.
   - `Q "SELECT value->>'error' FROM settings WHERE key='telegram.health'"` باید خالی باشد.
   - صف ارسال: `Q "SELECT kind, count(*) FILTER (WHERE done_at IS NOT NULL AND last_error IS NULL) AS ok, count(*) FILTER (WHERE last_error IS NOT NULL) AS err, count(*) FILTER (WHERE done_at IS NULL) AS pending FROM outbox GROUP BY kind ORDER BY kind"`. برای `alert` و `send_post` باید `ok` دست‌کم ۱ و `err` صفر باشد.
   - `Q "SELECT id, role, kind, created_at, last_edited_at FROM channel_posts ORDER BY id DESC LIMIT 3"` باید پست آزمایشی (`role` = `test`) را نشان دهد.
3. **ویرایش پست آزمایشی** (یک ویرایش، فقط در کانال آزمایشی):
   - ```
     Q "INSERT INTO outbox (kind, payload, attempts) SELECT 'edit_post', jsonb_build_object('post_id', id, 'text', 'پست آزمایشی Proxy-Hub ✅ ویرایش شد (پرامپت ۹). پست‌ها هرگز پاک نمی‌شوند، فقط ویرایش.'), 0 FROM channel_posts WHERE role='test' ORDER BY id DESC LIMIT 1 RETURNING id"
     ```
     شماره‌ی برگشتی را `J` بنام.
   - ۶۰ ثانیه صبر کن. سپس `Q "SELECT done_at IS NOT NULL, last_error FROM outbox WHERE id=<J>"` باید `t|` بدهد (انجام شده، بی خطا).
   - `Q "SELECT last_edited_at FROM channel_posts WHERE role='test' ORDER BY id DESC LIMIT 1"` باید زمانی تازه بدهد.
   - از مالک بپرس: «در کانال آزمایشی، متن پست آزمایشی به "✅ ویرایش شد (پرامپت ۹)" عوض شد؟»
4. **مسیر واقعی هشدار:**
   - ```
     sudo docker compose -p proxyhub exec -T alertmanager amtool --alertmanager.url=http://localhost:9093 alert add P09PathTest severity=warning --annotation=summary='آزمون مسیر هشدار (پرامپت ۹)' --annotation=description='اگر این پیام را در تلگرام دیدید، مسیر Alertmanager به پنل و ربات کار میکند. چیزی خراب نیست.'
     ```
   - ۹۰ ثانیه صبر کن. سپس از مالک بپرس: «یک هشدار "آزمون مسیر هشدار (پرامپت ۹)" در چت ربات رسید؟»
   - پایان هشدار: همان فرمان را با این اضافه بزن: `--end=$(date -u +%Y-%m-%dT%H:%M:%SZ)`. تا حدود ۵ دقیقه بعد ممکن است پیام «برطرف شد» هم برسد. این طبیعی است.
   - `sudo bash /opt/proxy-hub/deploy/monitoring/safe_logs.sh api 200 | grep -c 'alertmanager webhook'`. عدد را گزارش کن.
5. **توکن در لاگ نیست:**
   - `sudo docker compose -p proxyhub logs --no-color api worker alertmanager 2>&1 | grep -cE '[0-9]{8,10}:[A-Za-z0-9_-]{35}'` باید `0` بدهد.
   - فقط عدد را گزارش کن، نه خط‌ها.
6. **گزارش پایانی** فارسی در یک بلوک برای Claude ریپو: نتیجه‌ی هر گام، خروجی SQL گام‌های ۲ و ۳، و پاسخ مالک به دو پرسش گام‌های ۳ و ۴. برای هر خطا ۳۰ خط لاگ، فقط با `safe_logs.sh`. journal را با `-n 60` یا `--since` بخوان، نه ۴۰ خط.

**نکن:**
- توکن ربات، شناسه‌ی چت مالک یا متن کامل settings را در گزارش نیاور.
- چیزی به کانال اصلی نفرست. هیچ پیامی را حذف نکن.
- کلید توقف، سقف بودجه و سقف node را عوض نکن. توکن دیگری نخواه.
- `git push` نکن. هیچ شاخه یا ریپویی نساز یا پاک نکن.
