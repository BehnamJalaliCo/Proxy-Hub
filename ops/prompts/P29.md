# پرامپت ۲۹: چرا کانفیگ‌های Reality کار نمیکنند؟ (فقط سنجش)

> مالک این را میچسباند: «`git pull` بزن (روی `main`)، بعد فایل `ops/prompts/P29.md` را بخوان و تا رسیدن به نتیجه، خودت اجرا کن.»

قاعده‌های `ops/prompts/README.md` برقرار است:
- فارسی و **کوتاه** با مالک.
- هیچ uuid، کلید (`pbk`)، short id، لینک کامل یا IP کامل در گزارش نیاید. IP را فقط با ۲ بخش آخرش بنویس (مثل `…209.24`).
- commit یا push نکن.

فرمان‌ها:
- `Q() { sudo docker compose -p proxyhub exec -T postgres psql -U proxyhub -d proxyhub -At -c "$1"; }`
- `W() { sudo docker compose -p proxyhub logs --since "$1" worker 2>&1 | grep -E "reality|xray|target|Traceback" | tail -n 40; }`

**این پرامپت چیزی را عوض نمیکند.** فقط میسنجد و گزارش میدهد.

**گزارش مالک (۲۰۲۶-۱۱-۰۷، عصر):**
- هیچ‌کدام از کانفیگ‌های Reality کار نمیکند.
- «آپلود دارد ولی دانلود ندارد»، روی همراه اول.

**پرسش:** کانفیگ خراب است (کلید، کاربر، inbound، نام DNS)، یا ایران آن را میبندد (دامنه، IP، یا SNI روی IP هتزنر)؟

**یادآوری:**
- در P17 (۲۰۲۶-۱۱-۰۵)، Reality TCP روی hel1 با `github.com` از همراه اول ۸۴ تا ۱۹۰ مگابیت دانلود داشت.
- حالا nodeها در ash، hil و hel1 اند.
- D42: Reality با `dl.google.com` روی IP هتزنر از ایران هیچ سایتی باز نکرد.

0. **پیش‌شرط:** `deploy_status.sh` باید `RESULT: up to date` بدهد.
1. **تنظیم Reality:** `Q "SELECT value FROM settings WHERE key = 'reality'"`. گزارش کن: `enabled`، `transport`، `xhttp_enabled`، `target_mode`، `target_host`. اگر ردیفی نیست، پیش‌فرض‌ها برقرارند.
2. **کلید هر جایگاه و حال هر node:**
   - `Q "SELECT slot, target, server_name, created_at FROM reality_keys ORDER BY slot"`.
   - `Q "SELECT n.slot, n.location, s.enabled, s.up, s.target_ok, s.checked_server_name, s.apply_error, s.users_reported, s.xhttp_port, s.reported_at FROM reality_node_status s JOIN nodes n ON n.id = s.node_id WHERE n.state <> 'deleted' ORDER BY n.slot"`.
3. **کانفیگ‌ها:**
   - `Q "SELECT slot, transport, status, count(*), max(expires_at) FROM reality_configs GROUP BY 1, 2, 3 ORDER BY 1, 2, 3"`.
   - `Q "SELECT DISTINCT regexp_replace(host, '^[^.]+\.', '') FROM reality_configs WHERE status = 'active'"`. این دامنه‌ی لینک‌هاست، بی نام جایگاه.
4. **DNS از سرور پنل:** برای هر جایگاه فعال (`slotN.<دامنه‌ی گام ۳>`)، `getent ahostsv4 slotN.<دامنه> | head -1` را با `Q "SELECT slot, ipv4 FROM nodes WHERE state = 'ready' ORDER BY slot"` مقایسه کن. فقط ۲ بخش آخر IP را گزارش کن و بگو یکی‌اند یا نه.
5. **از ایران** (داده‌ی خود پنل؛ آزمون تازه نزن):
   - دامنه: `Q "SELECT z.name, z.pool_state, d.at, d.status, d.networks_answered, d.networks_hijacked FROM domain_checks d JOIN cf_zones z ON z.id = d.zone_id ORDER BY d.at DESC LIMIT 6"`. `networks_hijacked` بیش از ۰ یعنی DNS دامنه در ایران دستکاری میشود.
   - nodeها: `Q "SELECT n.slot, n.location, p.verdict, p.verdict_at FROM probe_node_state p JOIN nodes n ON n.id = p.node_id WHERE n.state <> 'deleted' ORDER BY n.slot"`.
   - `Q "SELECT n.slot, m.kind, m.port, m.status, count(*) FROM probe_measurements m JOIN nodes n ON n.id = m.node_id WHERE m.at > now() - interval '6 hours' GROUP BY 1, 2, 3, 4 ORDER BY 1, 2, 3, 4"`.
6. **آزمون خود لینک‌ها از سرور پنل (بیرون از ایران).** همان کاری را میکند که برنامه‌ی کاربر میکند:
   ```bash
   D="$(mktemp -d)"; chmod 700 "$D"
   bash node-image/fetch-xray.sh "$D"     # همان Xray نسخه‌ی node، با وارسی sha256
   sudo docker compose -p proxyhub exec -T api python - > "$D/links.jsonl" <<'PY'
   import asyncio, json
   from proxyhub.db.session import get_engine
   from proxyhub.reality.links import provide_links
   async def main():
       engine = get_engine()
       async with engine.connect() as db:
           for link in await provide_links(db):
               if link.kind == "reality" and link.status == "active":
                   print(json.dumps({"key": link.key, "slot": link.slot, "url": link.url}))
       await engine.dispose()
   asyncio.run(main())
   PY
   chmod 600 "$D/links.jsonl"; wc -l < "$D/links.jsonl"
   python3 ops/scripts/vless_selftest.py --xray "$D/xray" < "$D/links.jsonl"
   rm -rf "$D"
   ```
   - خروجی اسکریپت را **همان‌طور که هست** گزارش کن. uuid و کلید ندارد و IPها کوتاه شده‌اند.
   - برای هر لینک یک خط میآید: جایگاه، نوع (tcp یا xhttp یا ws)، درگاه، SNI، و سه نتیجه: `204`، `down` (۲۰ مگ) و `up` (۱۰ مگ)، با آخرین هشدار Xray.
   - `rm -rf "$D"` را فراموش نکن: لینک‌ها در آن پوشه‌اند.
7. **لاگ:** `W 3h`، بی uuid و بی IP کامل.
8. **گزارش پایانی** در یک بلوک کوتاه برای Claude ریپو: ردیف‌های گام‌های ۱ تا ۵، خروجی کامل گام ۶، و هر خطای گام ۷.

**نکن:**
- تنظیمات Reality، سایت هدف، transport یا هیچ چیز دیگری را عوض نکن.
- node نساز و حذف نکن.
- لینک، uuid یا کلید را در گزارش، لاگ یا فایلی بیرون از `$D` نگذار.
- `git push` نکن.
